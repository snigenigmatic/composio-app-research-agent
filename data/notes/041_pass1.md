Here are the Shopify integration research notes.

- Product: Shopify — ecommerce platform with Admin and Storefront APIs to build apps, manage store data, and power custom storefronts.
- Docs: https://shopify.dev/docs

Auth
- auth_methods: OAuth2; Bearer/PAT token (Admin API access token for custom/merchant-created apps)
- primary_auth: OAuth2

Access
- access: app_review
  - Rationale: You can self‑serve dev credentials and install on development stores, but public distribution across multiple merchants requires Shopify’s app review and approval.

API surface
- api_breadth: broad (Admin GraphQL/REST cover products, orders, customers, inventory, fulfillment, metafields, billing, etc.)
- OpenAPI spec: none official public (Admin REST/GraphQL are documented; GraphQL schema and official client libraries provided)
- Webhooks: yes (broad coverage; Events and classic webhooks)
- Sandbox: yes (development stores via Partner/Dev Dashboard)

MCP
- mcp: official
  - Notes: Shop MCP (buyer-side, hosted at mcp.shop.com) is available; a separate “Shopify MCP” for merchant‑side Admin actions is announced as “coming soon” in docs.

Buildability
- buildability: ready_with_caveats
- blocker: app_review
  - Caveats: Public distribution needs review; some scopes (e.g., protected customer data) need separate approval; Admin APIs are rate‑limited; REST Admin API is legacy (GraphQL required for new public apps as of Apr 1, 2025).

Additional notes for implementers
- Rate limits: GraphQL Admin API uses cost‑based throttling with per‑plan buckets; REST uses a leaky‑bucket by app/store. Design for retries/backoff or bulk operations. ([shopify.dev](https://shopify.dev/docs/apps/build/apis/graphql-admin/rate-limits?utm_source=openai))
- Protected customer data: public apps need separate approval for protected data and fields (name, address, email, phone). Development stores are exempt from review for testing. ([shopify.dev](https://shopify.dev/docs/apps/launch/protected-customer-data?utm_source=openai))
