Here are the integration research notes for Front (front.com).

- Product: Front — a customer operations platform combining shared inbox/help desk workflow with multichannel messaging, automation, and AI.
- Docs URL: https://dev.frontapp.com

Auth model
- auth_methods: OAuth2; API token (static bearer)  
- primary_auth: OAuth2

Access (how a developer gets creds)
- access: self_serve_free  
  - Free developer accounts provide a sandbox and allow creating apps, OAuth clients, and API tokens without contacting support.

API surface
- api_breadth: broad (Core API covers many entities: conversations, contacts, comments, inboxes, tags, etc.)

MCP
- mcp: official (Front ships an official MCP server to let AI assistants connect to Front)

Buildability for Composio
- buildability: ready_with_caveats
- blocker: app_review
  - Rationale: You can build and ship an OAuth-based connector today using self-serve developer creds. For broad distribution via Front’s App Store, there’s a partner publishing process and review. Some features (e.g., rule webhooks) and higher rate limits depend on plan/add-ons.

Other technical notes
- OpenAPI spec: Yes (public OpenAPI schemas for Core and Channel APIs; Postman workspace also available).
- Webhooks: Yes (application webhooks via apps; rule-based webhooks also supported; rule webhooks require Professional plan or above).
- Sandbox: Yes (free developer environment limited to 3 teammates).
- Rate limits: Default global per-plan limits; add-on available to increase limits.

Notes for Composio
- Best path: Implement OAuth2 (admin-authorized) for multi-tenant connections; use Core API + application webhooks when needed.  
- Distribution: Private app OAuth works immediately for customers; App Store listing later requires partner submission/review.  
- Plan caveats: If you depend on rule webhooks or need higher throughput, customers may need Professional+ and/or the API rate limit add-on (priced per 100 rpm on Pricing). ([front.com](https://front.com/pricing?utm_source=openai))
