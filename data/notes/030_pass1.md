Here are the research notes for: Vonage (Communications and Messaging)

- Product description: Cloud communications (CPaaS) platform offering Messaging (SMS/WhatsApp/RCS), Voice, Video, Verify, Numbers, Reports, and Network APIs.
- Docs URL: `https://developer.vonage.com`

Auth model
- auth_methods: 
  - API key and secret; Basic (base64 API key:secret) for some REST APIs. ([developer.vonage.com](https://developer.vonage.com/en/getting-started/concepts/authentication))
  - JWT/service account (application ID + private key) for Voice/Messages/RTC and most newer APIs; recommended for production. ([developer.vonage.com](https://developer.vonage.com/en/getting-started/concepts/authentication))
  - HMAC/signature (legacy SMS message signatures using SIGNATURE_SECRET). ([developer.vonage.com](https://developer.vonage.com/en/getting-started/concepts/authentication))
  - OAuth2 (Client Credentials) for CAMARA/Network APIs via Vonage’s OAuth token endpoint. ([developer.vonage.com](https://developer.vonage.com/en/auth/camara?utm_source=openai))
- primary_auth: JWT/service account (Vonage Applications mint JWTs; recommended for Messages/Voice). ([developer.vonage.com](https://developer.vonage.com/en/getting-started/concepts/authentication))

Access and gating
- access: self_serve_free (sign up creates an API key and secret; dashboard guides you to credentials; production use may require payment method and channel onboarding). ([developer.vonage.com](https://developer.vonage.com/en/getting-started/overview?source=dispatch&utm_source=openai))
- notable gatekeepers/caveats: 
  - Channel onboarding and compliance (e.g., WhatsApp external accounts, US 10DLC registration) and paid usage for live traffic; Messages API Sandbox is free but rate-limited. ([developer.vonage.com](https://developer.vonage.com/en/tutorials/send-fbm-message/prerequisites?utm_source=openai))

API surface
- api_breadth: broad (API reference spans Application, Numbers, Messages, Voice, Video, Verify, Reports, Identity Insights, Device Location Retrieval, etc.). ([developer.vonage.com](https://developer.vonage.com/en/api?utm_source=openai))

MCP
- mcp: official (Vonage provides official Documentation MCP Server and a Tooling/Server API Bindings MCP Server). ([s29.q4cdn.com](https://s29.q4cdn.com/651905246/files/doc_news/Vonage-Expands-Developer-Ecosystem-to-Accelerate-the-Next-Era-of-Enterprise-Digital-Transformation-2026.pdf))

Buildability for an agent toolkit (Composio)
- buildability: ready_with_caveats
  - Rationale: Credentials and APIs are self-serve and well-documented (ready), but live messaging/voice incur costs and some channels require onboarding/compliance; JWT-based auth requires per-tenant key handling (caveats). ([developer.vonage.com](https://developer.vonage.com/en/getting-started/concepts/authentication))
- blocker: none

Other implementation notes
- OpenAPI spec: Yes; Vonage states all APIs have public OpenAPI specs; API references provide a “Download OpenAPI Specification.” ([developer.vonage.com](https://developer.vonage.com/en/getting-started/concepts/openapi?source=dispatch&utm_source=openai))
- Webhooks: Yes; per capability (e.g., Voice answer/event URLs; Messages inbound/status). Signed webhooks enabled by default for Messages/Dispatch/Verify/Voice. ([developer.vonage.com](https://developer.vonage.com/en/application/technical-details?utm_source=openai))
- Sandbox: Yes; Messages API Sandbox (free; 100 messages/month; 1 rps; separate endpoint). Identity Insights also offers sandbox/test modes. ([developer.vonage.com](https://developer.vonage.com/en/messages/concepts/messages-api-sandbox?source=messages&utm_source=openai))
