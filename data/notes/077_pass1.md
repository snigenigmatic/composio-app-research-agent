ClickUp — Integration Research Notes (as of November 24, 2026)

- Product: ClickUp
- One‑liner: All‑in‑one work platform with a broad public REST API for tasks, docs, and workflows, plus an official MCP server for AI agents.
- Category: Productivity and Project Management
- Docs: https://developer.clickup.com
- Auth methods supported: OAuth2; Bearer/PAT token (personal API token)
- Primary auth for multi‑tenant apps: OAuth2
- Access: self_serve_free (API available on all plans; personal token and OAuth app creation are self‑serve)
- API breadth: broad (tasks, lists, folders, spaces, docs, comments, custom fields, time entries, views, webhooks, etc.; v2 and emerging v3 endpoints)
- MCP: official (ClickUp provides an MCP server)
- OpenAPI spec: yes (published by ClickUp; v2 and v3)
- Webhooks: yes (with HMAC signatures)
- Sandbox: none (use your own Workspace; personal token works for “Try it” in docs)
- Buildability for Composio: ready
- Blocker: none
- Notable caveats:
  - Rate limits apply per token and vary by Workspace plan; exceeding returns HTTP 429.
  - Only Workspace owners/admins can create OAuth apps.
  - Some endpoints are v3 and still rolling out; surface may evolve.

How to get credentials
- Personal API token: User generates in ClickUp Settings → Apps → API Token; tokens start with pk_ and do not expire. The header is Authorization: {personal_token} (no Bearer).
- OAuth app: A Workspace owner/admin creates an app in Settings → Apps, obtains client_id and client_secret; users authorize via https://app.clickup.com/api, then exchange code at https://api.clickup.com/api/v2/oauth/token; use Authorization: Bearer {access_token} on requests.
