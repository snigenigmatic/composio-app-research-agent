Ecwid — Research notes

- Product: Ecwid by Lightspeed — embeddable ecommerce platform to add a store to existing sites and sell across channels.
- Category: Ecommerce
- Docs URL: https://docs.ecwid.com/api-reference
- auth_methods: OAuth2; Bearer/PAT token (store-scoped secret_token/public_token for custom apps). ([docs.ecwid.com](https://docs.ecwid.com/get-started/make-your-first-api-request))
- primary_auth: OAuth2. ([docs.ecwid.com](https://docs.ecwid.com/get-started/make-your-first-api-request))
- access: paid_plan — “Only stores on paid plans can access API.” ([docs.ecwid.com](https://docs.ecwid.com/get-started/set-up-your-dev-environment-in-ecwid))
- api_breadth: broad (products, orders, customers, categories, discounts, shipping/payment, domains, staff, reports, etc.). ([docs.ecwid.com](https://docs.ecwid.com/api-reference/advanced/rest-api-calls))
- mcp: none known (no vendor-published MCP server for the API found).
- buildability: ready_with_caveats — API is well-documented and OAuth2-supported, but merchants must be on paid plans; app-market distribution requires validation if you want to list publicly. ([docs.ecwid.com](https://docs.ecwid.com/get-started/set-up-your-dev-environment-in-ecwid))
- blocker: paid_plan. ([docs.ecwid.com](https://docs.ecwid.com/get-started/set-up-your-dev-environment-in-ecwid))
- OpenAPI spec: none public found.
- Webhooks: yes (signed with X-Ecwid-Webhook-Signature). ([docs.ecwid.com](https://docs.ecwid.com/webhook-automations?utm_source=openai))
- Sandbox: No separate API sandbox/test mode; use a separate test store (Ecwid offers free upgrade for dev/test on request). ([docs.ecwid.com](https://docs.ecwid.com/get-started/make-your-first-api-request))

Notes for Composio
- Auth model: For multi-tenant agent tools, register a public app and use OAuth2 to get per-store access tokens. Custom single-store “secret_token” works without OAuth but is not suitable for multi-tenant user installs. ([docs.ecwid.com](https://docs.ecwid.com/get-started/make-your-first-api-request))
- Gating: API works only for merchants on paid plans; developers can request a free upgrade for a test store via support. Publishing in the App Market requires validation but external OAuth installs are possible without listing. ([docs.ecwid.com](https://docs.ecwid.com/get-started/set-up-your-dev-environment-in-ecwid))
- API surface: REST v3 with many resources (products, orders, customers, categories, discounts, shipping/payment, domains, staff, reports). Base URL: https://app.ecwid.com/api/v3/{storeId}. ([docs.ecwid.com](https://docs.ecwid.com/api-reference/advanced/rest-api-calls))
- Webhooks: Available, with HMAC-like signature header X-Ecwid-Webhook-Signature for verification. ([github.com](https://github.com/Ecwid/ecwid-api-docs/blob/master/includes/_webhooks.md?utm_source=openai))
- Rate limits: 600 requests/min per token. Plan for backoff on 429 with Retry-After. ([docs.ecwid.com](https://docs.ecwid.com/api-reference?utm_source=openai))
