Here’s what I found on Brex’s developer platform and how it fits Composio’s tooling model.

Research notes
- App: Brex
- Category: Finance and Fintech
- Product description: Unified spend platform (corporate cards, expense management, reimbursements, travel, bill pay) with a public developer API and an official MCP server. ([developer.brex.com](https://developer.brex.com/?utm_source=openai))
- Docs URL: https://developer.brex.com/ ([developer.brex.com](https://developer.brex.com/?utm_source=openai))

- auth_methods: OAuth2; Bearer/PAT token
  - PAT: Brex customers generate a “user token” in the dashboard and send it as an Authorization bearer header. ([developer.brex.com](https://developer.brex.com/guides/authentication?utm_source=openai))
  - OAuth2: Available for partners across REST APIs; Authorization Code for most APIs, Client Credentials for Onboarding; OpenID Connect-compliant. ([developer.brex.com](https://developer.brex.com/guides/partner_authentication?utm_source=openai))
  - MCP also supports OAuth (with dynamic client registration) and API key auth. ([developer.brex.com](https://developer.brex.com/docs/mcp))
- primary_auth: OAuth2
  - Rationale: There is a public, vendor-hosted MCP server that supports OAuth without partner preregistration (dynamic client registration). For direct REST integration outside MCP, OAuth is partner-gated; otherwise use PAT. ([developer.brex.com](https://developer.brex.com/docs/mcp))

- access: self_serve_free
  - Any Brex customer can enable Developer API and create tokens; Essentials plan ($0/user) lists “Brex API access.” MCP access is enabled by an account admin via beta settings. ([brex.com](https://www.brex.com/pricing))

- api_breadth: broad
  - Documented services include Accounting, Budgets, Expenses, Fields, Onboarding, Payments, Team, Transactions, Travel, Webhooks; OpenAPI-based REST. ([developer.brex.com](https://developer.brex.com/?utm_source=openai))

- mcp: official
  - Brex hosts an official MCP server at https://api.brex.com/mcp (Beta). ([developer.brex.com](https://developer.brex.com/docs/mcp))

- buildability: ready_with_caveats
  - Why: Composio can ship today using PAT on REST and/or OAuth via MCP. Caveats: full OAuth for REST is partner-only; MCP is in beta and feature-set may evolve; some actions are read-mostly. ([developer.brex.com](https://developer.brex.com/guides/partner_authentication?utm_source=openai))

- blocker: partner_program
  - Only if Composio requires REST OAuth Authorization Code for multi-tenant flows. PAT- or MCP-based builds are not blocked. ([developer.brex.com](https://developer.brex.com/guides/partner_authentication?utm_source=openai))

- OpenAPI spec: yes (“defined using the OpenAPI specification”). ([developer.brex.com](https://developer.brex.com/?utm_source=openai))
- Webhooks: yes (real-time events; see Webhooks API/guide). ([developer.brex.com](https://developer.brex.com/guides/webhooks?utm_source=openai))
- Sandbox/staging: yes (api-staging.brex.com; data may be purged, for point-in-time testing). ([developer.brex.com](https://developer.brex.com/guides/partner_authentication?utm_source=openai))

- API surface highlights (non-exhaustive):
  - Team: users, departments, locations, titles, cards
  - Expenses: card expenses (filters, receipts, attendees), reimbursements
  - Transactions: card and cash accounts/transactions, statements
  - Payments: vendors, ACH/wires/checks transfers
  - Accounting: integrations and records
  - Budgets/Spend limits, Travel, Fields, Onboarding, Webhooks
  - All REST APIs are JSON over HTTPS with standard verbs/codes. ([developer.brex.com](https://developer.brex.com/?utm_source=openai))

Implementation takeaways for a Composio toolkit
- Best default auth for agents: OAuth2 via the official MCP server (no app review; dynamic client registration). Fall back to PAT for REST if customers don’t enable MCP beta. ([developer.brex.com](https://developer.brex.com/docs/mcp))
- If you need REST OAuth Authorization Code (outside MCP), expect partner gating. ([developer.brex.com](https://developer.brex.com/guides/partner_authentication?utm_source=openai))
- Provide optional webhook registration for near-real-time sync. ([developer.brex.com](https://developer.brex.com/guides/webhooks?utm_source=openai))
- Use staging host for integration tests; do not rely on data persistence. ([developer.brex.com](https://developer.brex.com/guides/partner_authentication?utm_source=openai))
