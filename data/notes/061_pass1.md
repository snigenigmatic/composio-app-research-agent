Here are the Composio-ready research notes for GitHub.

Product: GitHub — code hosting and collaboration with REST and GraphQL APIs for automation and integrations

Auth model:
- auth_methods: OAuth2; Bearer/PAT token; JWT/service account; Basic
- primary_auth: JWT/service account (GitHub App private key → JWT → installation access token; OAuth2 is available for OAuth apps, but GitHub recommends GitHub Apps for org/on-behalf-of use)

Access to credentials:
- access: self_serve_free

API surface:
- api_breadth: broad

MCP:
- mcp: official

Buildability for an agent toolkit:
- buildability: ready
- blocker: none

Docs URL:
- https://docs.github.com/en/rest

Spec, webhooks, sandbox:
- OpenAPI spec: yes
- Webhooks: yes
- Sandbox: no dedicated sandbox environment documented (use personal/org test repos and orgs)

Concise notes and rationale:
- Public, well‑documented REST API with an official OpenAPI description; GraphQL API also available.
- Multiple auth paths: PATs (fine‑grained preferred), OAuth Apps (OAuth 2.0), and GitHub Apps which authenticate via a short‑lived installation token minted using a JWT signed by the app’s private key; some app endpoints use Basic with client_id:client_secret.
- Credentials are self‑serve: any user/org admin can register OAuth apps or GitHub Apps in settings; no paid plan or partner gating to start. Marketplace listing/verification is optional and separate.

Extra implementation details (for Composio):
- Primary scopes/permissions: GitHub Apps use fine‑grained permissions per resource area; OAuth Apps use OAuth scopes; PATs use fine‑grained permissions or classic scopes. ([docs.github.com](https://docs.github.com/en/rest/authentication/authenticating-to-the-rest-api?apiVersion=2022-11-28))
- Rate limits: per‑token and per‑app limits apply; GitHub Apps have distinct limits vs user tokens (see “Rate limits for GitHub Apps” in docs if needed). ([docs.github.com](https://docs.github.com/en/apps/creating-github-apps/registering-a-github-app))
