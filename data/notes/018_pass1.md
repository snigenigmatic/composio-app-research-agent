Help Scout — Integrations Research Notes (Support and Helpdesk)

Product: Email-first help desk with shared inboxes, live chat (Beacon), knowledge base (Docs), reporting, and an apps platform.

Auth model (what exists)
- auth_methods: OAuth2; Basic; HMAC/signature (for webhook verification)
- primary_auth: OAuth2 (Authorization Code for multi-tenant apps; Client Credentials for internal)
How to get credentials
- Mailbox/Chat APIs (Inbox + Chat): Create an OAuth2 app in the Help Scout UI (Your Profile > My apps) to obtain Client ID/Secret; use OAuth 2.0 Authorization Code or Client Credentials flows.
- Docs API: Each user has a Docs API key (Your Profile > Security and Access); authenticate via HTTP Basic with the API key as the username and a dummy password.
- Webhooks: Configure in-app (Settings > Workspace > Apps > Webhooks); verify requests via X-HelpScout-Signature (HMAC).

Access gating (plans / review)
- access: paid_plan (API access isn’t on the Free plan; Standard/Plus/Pro include API with differing limits and endpoints)
- Notes:
  - Standard: Up to 200 calls/min; no Reporting API.
  - Plus: Up to 400 calls/min; Reporting API available.
  - Pro: Up to 800 calls/min; Reporting API available.
  - 15‑day free trial exists on paid tiers, but Free plan excludes API.

API surface
- api_breadth: broad (Inbox/Conversations, Threads, Mailboxes, Customers, Users, Tags, Attachments, Workflows, Reports; plus Chat API for live Beacon chats; Docs API for KB content; Webhooks)
- Key surfaces called out by vendor: Inbox API, Chat API, Docs API, Webhooks, Apps (sidebar apps with JS SDK/UI kit).

MCP
- mcp: official
- Notes: Help Scout hosts an official remote MCP server (read‑only for new connections) at mcp.helpscout.net/mcp; available on any plan with API access (Standard/Plus/Pro). Reporting tools via MCP require Plus/Pro.

Buildability for an agent toolkit (Composio)
- buildability: ready_with_caveats
- Why: Credentials are self‑serve within the product UI and APIs are well‑documented; however, API access requires a paid plan and reporting endpoints are gated to Plus/Pro; rate limits vary by plan.
- blocker: paid_plan

Docs URL
- https://developer.helpscout.com/

OpenAPI spec / Webhooks / Sandbox
- OpenAPI spec: none official published in vendor docs (did not find an official OpenAPI/Swagger spec).
- Webhooks: yes (multiple events including conversations and Beacon chat events; HMAC signature header).
- Sandbox: no separate API sandbox; use a paid plan (trial available) to develop and test.

Scope notes and caveats
- Reporting endpoints (e.g., /v2/reports/…) are explicitly limited to Plus/Pro. ([developer.helpscout.com](https://developer.helpscout.com/mailbox-api/endpoints/reports/conversations/reports-conversations-overall/?utm_source=openai))
- Credentials must map to an active, invited user; otherwise 401. ([developer.helpscout.com](https://developer.helpscout.com/mailbox-api/overview/authentication/?utm_source=openai))
- Docs API has separate rate limits based on number of Docs sites (not the same as Inbox API plan limits). ([developer.helpscout.com](https://developer.helpscout.com/docs-api/))
