Here are the integration research notes for: Salesforce Commerce Cloud (B2C)

- Product description: Enterprise ecommerce platform (formerly Demandware) with headless and traditional storefront options, exposing B2C Commerce APIs (SCAPI) and legacy OCAPI for storefront and back-office use cases. ([developer.salesforce.com](https://developer.salesforce.com/docs/commerce/b2c-commerce/guide/api-doc.html?utm_source=openai))
- Docs URL: https://developer.salesforce.com/docs/commerce

Access and auth
- auth_methods: OAuth2 (JWT bearer tokens). Shopper APIs use SLAS OAuth flows; Admin APIs use Account Manager OAuth 2.0. ([developer.salesforce.com](https://developer.salesforce.com/docs/commerce/b2c-commerce/guide/authorization.html?utm_source=openai))
- primary_auth: OAuth2. ([developer.salesforce.com](https://developer.salesforce.com/docs/commerce/b2c-commerce/guide/authorization.html?utm_source=openai))
- access: contact_sales (customers get API at no extra cost once they have a B2C Commerce org; API clients are created in Account Manager by an org admin; on‑demand sandboxes require purchased credits; partners can get access via the Salesforce partner program). ([developer.salesforce.com](https://developer.salesforce.com/docs/commerce/commerce-api/guide/scapi-get-started.html?utm_source=openai))

API surface and tooling
- api_breadth: broad (Shopper and Admin APIs across catalog, products, baskets/orders, pricing/promotions, inventory, content, etc.; plus OCAPI and Custom APIs). ([developer.salesforce.com](https://developer.salesforce.com/docs/commerce/commerce-api/guide/develop.html?utm_source=openai))
- mcp: official (Salesforce ships an official B2C DX MCP server and related tooling). ([developer.salesforce.com](https://developer.salesforce.com/docs/commerce/commerce-api/guide/b2c-developer-tooling.html?utm_source=openai))
- buildability: ready_with_caveats — API is well‑documented and standard OAuth2, but customers must provision API clients in Account Manager/SLAS and exposure varies by org, environment, and scopes. ([developer.salesforce.com](https://developer.salesforce.com/docs/commerce/b2c-commerce/guide/authorization.html?utm_source=openai))
- blocker: enterprise_sales (requires a customer org or partner access to obtain working credentials/sandboxes). ([developer.salesforce.com](https://developer.salesforce.com/docs/commerce/b2c-commerce/guide/b2c-developer-sandboxes.html?utm_source=openai))

Other implementation notes
- OpenAPI spec: Yes. SCAPI specs are OAS3; Custom APIs require an OAS 3.0 schema. ([developer.salesforce.com](https://developer.salesforce.com/docs/commerce/commerce-api/references/about-commerce-api/about.html?utm_source=openai))
- Webhooks: Limited. Platform supports eCDN notification “webhook destination” registrations; there isn’t a general resource‑event webhook framework for SCAPI (extensions use server‑side “hooks” in code). ([help.salesforce.com](https://help.salesforce.com/s/articleView?id=cc.b2c_create_ecdn_notification_destination.htm&language=en_US&type=5&utm_source=openai))
- Sandbox: Yes. On‑Demand Sandboxes exist; customers purchase sandbox credits; partner ODS access is gated by the partner program. ([developer.salesforce.com](https://developer.salesforce.com/docs/commerce/b2c-commerce/guide/b2c-developer-sandboxes.html?utm_source=openai))
