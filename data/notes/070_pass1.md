Sentry — Integration Research Notes (Nov 24, 2026)

- Product: Sentry is a developer observability platform for error tracking, performance, profiling, and related telemetry across apps and services.
- Docs URL: https://docs.sentry.io/api/

Auth model
- auth_methods: OAuth2 | Bearer/PAT token | Basic (legacy API keys) | Other (DSN for limited endpoints)
- primary_auth: OAuth2
- What I saw:
  - OAuth2 for third‑party apps acting on behalf of users/orgs. Personal tokens and “internal integration” tokens are also available from the UI; legacy API keys are disabled for new accounts; some endpoints allow DSN auth. ([docs.sentry.io](https://docs.sentry.io/api/auth/?utm_source=openai))

Access to credentials
- access: self_serve_free
- What I saw:
  - You can create auth tokens in the product (User settings → Personal Tokens) and via “internal integrations.” No plan gate is stated in the auth docs. Public (multi‑tenant) integrations require a Sentry review to be listed/installed by other orgs. ([docs.sentry.io](https://docs.sentry.io/api/auth/?utm_source=openai))

API surface
- api_breadth: broad
- What I saw:
  - The API covers organizations, teams, projects, issues/events, alerts, service hooks, releases, SCIM, tracing/profiling, etc.; v0 with many documented endpoints. An official OpenAPI spec is published. ([docs.sentry.io](https://docs.sentry.io/api/?utm_source=openai))

MCP
- mcp: official
- What I saw:
  - Sentry ships an official MCP server so agents can query Sentry data; vendor blog and mcp.sentry.dev reference it. ([blog.sentry.io](https://blog.sentry.io/introducing-mcp-server-monitoring/?bb=240686))

Buildability for an agent toolkit
- buildability: ready_with_caveats
- blocker: app_review
- Rationale:
  - You can ship today using user-scoped or internal-integration tokens (self‑serve). For a first‑class multi‑tenant OAuth app that any Sentry org can install, Sentry requires a publication review; plan for rate limits and prefer webhooks to polling. ([sentry.help](https://www.sentry.help/en/articles/13964035-how-to-submit-a-public-integration-publication-request-in-sentry))

Other implementation notes
- OpenAPI spec: Yes (OpenAPI 3.0 JSON in getsentry/sentry repo; separate schema repo and generated TS client). ([github.com](https://github.com/getsentry/sentry/blob/master/api-docs/openapi.json?utm_source=openai))
- Webhooks: Yes
  - Two options:
    - Service Hooks at the project level (event.created, event.alert, etc.). ([docs.sentry.io](https://docs.sentry.io/api/projects/register-a-new-service-hook/?utm_source=openai))
    - Integration Platform webhooks for custom/public integrations, with configurable webhookEvents. ([docs.sentry.io](https://docs.sentry.io/api/integration/update-an-existing-custom-integration/?utm_source=openai))
- Sandbox: No dedicated sandbox environment documented. You can develop on a free org or self‑hosted Sentry; internal integrations and personal tokens are self‑serve. ([docs.sentry.io](https://docs.sentry.io/api/auth/?utm_source=openai))
- Rate limits: All API requests are rate‑limited; responses include X‑Sentry‑Rate‑Limit-* headers; Sentry recommends using webhooks to avoid polling. ([docs.sentry.io](https://docs.sentry.io/api/ratelimits/?utm_source=openai))
