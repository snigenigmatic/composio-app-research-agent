Here are the integration research notes for: Threads (Meta)

- Product: Threads API (Meta)
- One‑liner: Meta’s Threads Graph API lets apps post on behalf of a user, retrieve media and profiles, moderate replies, run keyword/profile discovery, and fetch insights. ([developers.facebook.com](https://developers.facebook.com/documentation/threads))
- Docs URL: https://developers.facebook.com/docs/threads (redirects to the Threads documentation hub). ([developers.facebook.com](https://developers.facebook.com/documentation/threads))

Auth model
- auth_methods: OAuth2
- primary_auth: OAuth2
- Details: “API authentication is handled by Threads user access tokens that conform to the OAuth 2.0 protocol… Short‑lived access tokens are valid for 1 hour… [can be exchanged for] long‑lived tokens.” Long‑lived tokens are valid 60 days and refreshable. ([developers.facebook.com](https://developers.facebook.com/documentation/threads/get-started))

Access and gating
- access: app_review
- Details: You can self‑serve by creating a Meta app and selecting the “Threads” use case; testers can grant permissions at any time. For non‑role users, each permission “must first be approved through the App Review process, and your app must be published.” Webhooks require Live mode (non‑tech providers) or advanced access (tech providers) and business verification. ([developers.facebook.com](https://developers.facebook.com/documentation/threads/get-started))

API surface
- api_breadth: moderate
- Why: Official docs cover posting (text/image/video/carousel/quotes), profile and profile discovery, mentions, replies and moderation (hide/unhide, reply controls, approvals), insights, keyword/tag search, and webhooks; not a full social graph or DMs. ([developers.facebook.com](https://developers.facebook.com/documentation/threads))

MCP availability
- mcp: community
- Notes: No official MCP from Meta; multiple third‑party/open‑source MCP servers exist that wrap the Threads API. (Example repositories exist but are not vendor‑official.)

Buildability
- buildability: ready_with_caveats
- blocker: app_review
- Rationale: You can ship today using self‑serve developer apps and Threads Testers; production‑grade usage (permissions beyond testers, webhooks at scale) requires App Review, Live mode/advanced access, and business verification. ([developers.facebook.com](https://developers.facebook.com/documentation/threads/get-started))

Other key implementation facts
- Hosts: graph.threads.com and graph.threads.net are both valid. ([developers.facebook.com](https://developers.facebook.com/documentation/threads/overview))
- Rate limits: Posting cap 250 posts per profile per rolling 24h; replies cap 1,000 per 24h; per‑impression call budgets and CPU/time budgets apply; usage is queryable via /{threads-user-id}/threads_publishing_limit. ([developers.facebook.com](https://developers.facebook.com/documentation/threads/overview))
- Publishing model: two‑step container create (POST /{threads-user-id}/threads) then publish (POST /{threads-user-id}/threads_publish). Requires threads_basic + threads_content_publish. ([developers.facebook.com](https://developers.facebook.com/documentation/threads/posts))
- Webhooks: Add “Threads webhooks” sub‑use case, subscribe to topics (replies, mentions, delete, publish), meet Live/advanced‑access and business‑verification requirements. ([developers.facebook.com](https://developers.facebook.com/documentation/threads/webhooks))

Ecosystem/supplementary
- OpenAPI spec: No official OpenAPI published; Meta provides an official Postman collection. (Docs index links “Postman Collection.”) ([developers.facebook.com](https://developers.facebook.com/documentation/threads))
- Webhooks: Yes (official). ([developers.facebook.com](https://developers.facebook.com/documentation/threads/webhooks))
- Sandbox: Yes — Development mode with “Threads Testers” who can grant permissions without App Review. ([developers.facebook.com](https://developers.facebook.com/documentation/threads/get-started))
