Cloudflare — Research notes for Composio

- Product: Cloudflare
- One‑liner: Global Internet network and developer platform (security, performance, serverless Workers) with a very broad public API across products.
- Category: Developer, Infra and Data platforms
- Docs URL: https://developers.cloudflare.com/api/

Auth model
- auth_methods: OAuth2; Bearer/PAT token (scoped API Tokens); API key (Global API Key; legacy/less secure)
- primary_auth: OAuth2

Access gating
- access: self_serve_free
  - Rationale: OAuth apps and API tokens can be created self‑serve on any plan (incl. Free).
- app_review nuance: Public OAuth apps require domain verification; docs do not indicate manual platform review.

API surface
- api_breadth: broad (thousands of operations across most Cloudflare products)

MCP
- mcp: official (managed remote MCP servers published by Cloudflare)

Buildability for Composio
- buildability: ready
- blocker: none
- Notes: Best default is OAuth2 for multi‑tenant agent authorization; API Tokens remain viable for CI/service flows. Extremely broad surface and official MCP server make rapid coverage possible.

Other implementation details
- OpenAPI spec: yes (official, single bundled spec)
- Webhooks: yes (Notifications webhooks across all plans)
- Sandbox: no dedicated sandbox; use a regular Cloudflare account (Free plan works) for development and testing.

Notes/caveats observed
- Public OAuth app visibility requires domain verification; apps start private by default. No explicit app review is documented for going public. ([developers.cloudflare.com](https://developers.cloudflare.com/fundamentals/oauth/create-an-oauth-client/))
- API Keys are supported but discouraged vs scoped API Tokens. Some legacy/edge cases in third‑party tooling may still mention the Global API Key. ([developers.cloudflare.com](https://developers.cloudflare.com/fundamentals/api/get-started/))
