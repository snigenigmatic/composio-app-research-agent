Here’s what I found on HubSpot as an integration target.

- auth_methods: OAuth2; Bearer/PAT token (Service Keys; legacy Private App tokens)
- primary_auth: OAuth2 (for multi-tenant/public apps installed to a customer’s HubSpot via consent)
- access: self_serve_free (free developer account + test accounts; credentials self-serve). ([developers.hubspot.com](https://developers.hubspot.com/developer-platform-basics))
- api_breadth: broad (CRM objects, associations, pipelines/properties, marketing, CMS, conversations, revenue, webhooks, etc.). ([developers.hubspot.com](https://developers.hubspot.com/docs/api-reference/latest/overview))
- mcp: official (HubSpot provides official MCP servers and docs). ([developers.hubspot.com](https://developers.hubspot.com/changelog/hubspot-developer-mcp-server-for-app-and-cms-development-now-in-ga?utm_source=openai))
- buildability: ready (self-serve creds, extensive APIs, OAuth works today; marketplace listing is optional)
- blocker: none

Key details and caveats for an agent toolkit
- Auth today: OAuth 2.0 for public/multi-tenant apps; Service Keys for single-account, system‑to‑system data integrations (bearer token). HubSpot has begun sunsetting creation of new legacy Private Apps and directs new in‑account integrations to Service Keys. ([developers.hubspot.com](https://developers.hubspot.com/docs/api-reference/latest/authentication/manage-oauth-tokens))
- Distribution: You can distribute a public OAuth app via direct install without a Marketplace listing. Listing/certification adds review requirements but isn’t required to run an integration. ([developers.hubspot.com](https://developers.hubspot.com/changelog/app-listing-and-app-certification-requirement-updates-for-may-2026?utm_source=openai))
- MCP: If you plan AI agent features, HubSpot’s official MCP servers (developer/local and remote) exist, with documented scope/limits. ([developers.hubspot.com](https://developers.hubspot.com/changelog/hubspot-developer-mcp-server-for-app-and-cms-development-now-in-ga?utm_source=openai))

Why “ready”
