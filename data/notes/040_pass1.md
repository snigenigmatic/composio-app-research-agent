Here’s what I found from SendGrid’s primary docs and pages, current as of November 24, 2026.

Research notes
- Product: Twilio SendGrid — cloud email delivery and marketing platform (Email API + Marketing Campaigns)
- Docs URL: https://www.twilio.com/docs/sendgrid/api-reference
- auth_methods: API key (used as Bearer token)
- primary_auth: API key (Authorization: Bearer)
- access: self_serve_trial (new accounts start on a 60‑day trial; free plans were retired in 2025)
- api_breadth: broad (mail send, templates, contacts/marketing, suppressions, stats, settings, webhooks, etc.)
- mcp: community (third‑party MCP servers exist; no official SendGrid MCP that executes API calls)
- buildability: ready_with_caveats
- blocker: paid_plan (trial expires; ongoing production use requires a paid plan)
- OpenAPI spec: Yes (official OpenAPI spec repo published by Twilio/SendGrid)
- Webhooks: Yes — Event Webhook (delivery/engagement events) and Inbound Parse Webhook (ingest incoming mail)
- Sandbox: No separate sandbox environment, but Mail Send “Sandbox Mode” validates requests without delivering mail

Why these classifications
- primary_auth = API key because SendGrid’s REST API is authenticated via an API key passed as a Bearer token; there is no public OAuth app flow for third‑party multi‑tenant tools. ([twilio.com](https://www.twilio.com/docs/sendgrid/api-reference/how-to-use-the-sendgrid-v3-api/authentication?utm_source=openai))
- access = self_serve_trial since anyone can sign up and get credentials during a 60‑day trial; permanent free plans were retired in 2025. ([twilio.com](https://www.twilio.com/en-us/products/email-api/pricing?utm_source=openai))
- api_breadth = broad based on first‑party API reference coverage. ([twilio.com](https://www.twilio.com/docs/sendgrid/api-reference?utm_source=openai))
- mcp = community because only third‑party MCP servers are available; no vendor‑maintained server that executes SendGrid actions was found. ([github.com](https://github.com/deyikong/sendgrid-mcp?utm_source=openai))
- buildability = ready_with_caveats and blocker = paid_plan since Composio can integrate now with API keys, but customers will need a paid plan after the trial for production.
