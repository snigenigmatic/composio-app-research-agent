Airtable — Research notes for Composio agent toolkit

Product: Airtable
One-line description: Spreadsheet‑meets‑database platform with REST API, webhooks, and an official MCP server for AI agents. 

Docs URL: https://airtable.com/developers

Auth model
- auth_methods: OAuth2; Bearer/PAT token (scoped Personal Access Tokens) ([airtable.com](https://airtable.com/developers/web/api/authentication))
- primary_auth: OAuth2 (recommended for third‑party apps acting on a user’s account) ([airtable.com](https://airtable.com/developers/web/api/authentication))

Access
- access: self_serve_free (API available on all plans; PATs can be created on all plans) ([support.airtable.com](https://support.airtable.com/articles/9906627822-options-for-integrating-with-airtable))
- Notes on gating: Some endpoints/scopes are Enterprise‑only (marked “Enterprise” in docs); Enterprise orgs may restrict API usage via admin policies. ([support.airtable.com](https://support.airtable.com/articles/9906627822-options-for-integrating-with-airtable))

API surface
- api_breadth: broad (records CRUD, schema/table/field management, views, automations, permissions/org mgmt on Enterprise, webhooks) ([airtable.com](https://airtable.com/developers/web/api/introduction))
- Style: REST, JSON, standard HTTP codes. ([airtable.com](https://airtable.com/developers/web/api/introduction))

MCP
- mcp: official (Airtable’s own MCP server; works with Claude, ChatGPT, etc.) ([airtable.com](https://airtable.com/developers/agents/mcp/getting-started))

Buildability for Composio
- buildability: ready_with_caveats
- blocker: other (rate limits; some useful endpoints are Enterprise‑only)
- Rationale: Self‑serve OAuth and PATs, public REST + webhooks make it straightforward. Consider API call limits and that certain scopes/endpoints (e.g., some views/permissions/org management) are Enterprise‑only. ([support.airtable.com](https://support.airtable.com/articles/7735693959-Managing-API-call-limits-in-Airtable?utm_source=openai))

Other implementation details
- OpenAPI spec: No official OpenAPI/Swagger spec published in developer docs; there is an official Postman collection. (Confidence: medium.) ([postman.com](https://www.postman.com/airtable/airtable-web-api-workspace/collection/0ip5uf8/airtable-web-api?utm_source=openai))
- Webhooks: Yes (first‑class Webhooks API; list/create endpoints; all plans). ([support.airtable.com](https://support.airtable.com/articles/7385030819-airtable-webhooks-api-overview))
- Sandbox: No separate sandbox environment documented; free plan/dev workspaces and PATs serve for development. PATs available on all plans. ([support.airtable.com](https://support.airtable.com/articles/9934989703-Creating-personal-access-tokens))

How a developer gets credentials
- Personal Access Tokens: Self‑serve in Developer Hub at airtable.com/create/tokens; choose scopes and specific bases/workspaces. ([airtable.com](https://airtable.com/developers/web/guides/personal-access-tokens))
- OAuth client: Self‑register at airtable.com/create/oauth, then use standard OAuth 2.0 grant to obtain access/refresh tokens; end users grant base/workspace access at consent. ([airtable.com](https://airtable.com/developers/web/api/authentication))
- Enterprise: Optional service accounts and org‑level API policies/allow‑lists. ([support.airtable.com](https://support.airtable.com/articles/9934989703-Creating-personal-access-tokens))
