Here are the integration research notes for Stripe.

- App: Stripe
- Category: Finance and Fintech
- Product description: Payments and financial infrastructure platform with APIs for payments, payouts, subscriptions/invoicing, identity, and Connect for multi-party platforms. ([docs.stripe.com](https://docs.stripe.com/api))
- Docs URL: https://docs.stripe.com/api ([docs.stripe.com](https://docs.stripe.com/api))

Auth model
- auth_methods: OAuth2; API key. Stripe supports OAuth 2.0 for Connect to act on other accounts, and API keys for direct API calls. ([docs.stripe.com](https://docs.stripe.com/connect/oauth-reference))
- primary_auth: OAuth2 (Connect OAuth) for a multi-tenant agent that needs end users to grant access to their Stripe accounts; after OAuth, Stripe recommends using the Stripe-Account header with your platform key to call APIs for connected accounts. ([docs.stripe.com](https://docs.stripe.com/connect/oauth-reference))

Access and gating
- access: self_serve_free. Anyone can sign up, get test keys/sandboxes, and go live after self-serve account activation/KYC. ([support.stripe.com](https://support.stripe.com/topics/getting-started?utm_source=openai))
- notes on gating: Some products/capabilities (e.g., Issuing, Treasury, certain configs) require enabling specific capabilities or using Accounts v1; this is configuration/eligibility rather than paywalling API access. ([docs.stripe.com](https://docs.stripe.com/connect/accounts-v2))

API surface
- api_breadth: broad (full-stack payments/finance APIs across v1 and v2; official OpenAPI spec covers GA and preview endpoints). ([github.com](https://github.com/stripe/openapi?utm_source=openai))
- OpenAPI spec: Yes (stripe/openapi repo). ([github.com](https://github.com/stripe/openapi?utm_source=openai))
- Webhooks: Yes (first-class webhook/event destinations with signing). ([docs.stripe.com](https://docs.stripe.com/webhooks))
- Sandbox: Yes (general sandboxes and test mode). ([docs.stripe.com](https://docs.stripe.com/sandboxes))

MCP (Model Context Protocol)
- mcp: official. Stripe publishes a hosted MCP server for agents. ([github.com](https://github.com/stripe/ai/blob/main/tools/modelcontextprotocol/README.md?utm_source=openai))

Buildability for Composio
- buildability: ready_with_caveats
- why: Self-serve credentials and comprehensive docs make it buildable now. Caveats: Connect/OAuth flow for acting on user accounts; rate limits; some capabilities need enablement/review; governance of agent access is advisable (Stripe supports agent-tagged restricted keys). ([docs.stripe.com](https://docs.stripe.com/connect/authentication))
- blocker: none

Research details for implementers
- How an agent would auth today:
  - Connect OAuth to link a user’s Stripe account (obtain stripe_user_id; token_type is bearer but access_token is deprecated). Then use your platform’s API key plus Stripe-Account header to act for that account. ([docs.stripe.com](https://docs.stripe.com/connect/oauth-reference))
  - For first‑party (single tenant) use, use API keys (prefer Restricted API Keys); Basic or Bearer auth are supported. ([docs.stripe.com](https://docs.stripe.com/api/authentication))
- Rate limits: Stripe documents rate limits/allocations for API endpoints (plan for retries/backoff). ([docs.stripe.com](https://docs.stripe.com/connect/authentication))

Extras
- Webhooks: deliver HTTPS JSON payloads; verify signatures with whsec_ secrets. ([docs.stripe.com](https://docs.stripe.com/webhooks))
- Sandboxes: general sandboxes recommended over legacy test‑mode sandbox; can be created and shared for isolated testing. ([docs.stripe.com](https://docs.stripe.com/sandboxes))
