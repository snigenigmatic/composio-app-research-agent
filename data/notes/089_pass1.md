Here’s what I found for Ramp (ramp.com)

- Product: Corporate card, expense management, bill pay, procurement, and finance automation platform
- Docs URL: https://docs.ramp.com/developer-api
- Primary_auth: OAuth2
- Auth_methods: OAuth2 (client credentials and authorization code; token at /developer/v1/token)
- How to get creds:
  - Customers: Admins can create a “developer app” in their Ramp account to get client_id/client_secret
  - Sandbox: Self-serve request for a seeded sandbox; uses separate base URL and credentials
  - Public/partner apps: Use the Developer Console; requires partner application + app production review
- Access: app_review (self-serve credentials exist, but publishing a multi-tenant OAuth app requires review; partner application also required)
- API surface: broad (cards, funds, transactions, bills, reimbursements, users, procurement, custom records, webhooks, AI usage, etc.)
- Base URLs:
  - Production API: https://api.ramp.com
  - Sandbox API: https://demo-api.ramp.com
- Webhooks: Yes (subscribe via API; HMAC-SHA256 signature in X-Ramp-Signature; verification handshake + retries)
- OpenAPI spec: Yes (docs-hosted canonical spec)
- Sandbox: Yes (seeded demo business; separate creds and base URL)
- MCP: official (Ramp runs MCP servers to connect assistants like ChatGPT/Claude/Cursor to a user’s Ramp account; also a Ramp CLI)
- mcp: official
- api_breadth: broad
- access: app_review
- buildability: ready_with_caveats
- blocker: partner_program
- Notes on gating/tiers:
  - Internal/one-tenant builds are immediately doable with self-serve creds
  - To ship a multi-tenant agent integration (Composio-style), you’ll need acceptance to Ramp’s Technology Partner Program and separate production approval for the app listing/use of OAuth scopes
