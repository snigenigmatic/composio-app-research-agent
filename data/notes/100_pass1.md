Grain — integrations research notes (updated Nov 24, 2026)

Summary
- One‑line: Grain is an AI meeting memory platform that records or ingests calls, generates notes/action items, and exposes meeting data via a public API and an official MCP server.
- Docs URL: https://developers.grain.com/

Auth model
- auth_methods: OAuth2; Bearer/PAT token (personal access token and workspace access token)
- primary_auth: OAuth2 (Authorization Code with PKCE; personal or workspace scopes)

Access/gating
- access: self_serve_free
  - Notes: Personal Access Tokens are available on all plans; OAuth “public clients” can self‑register via client metadata. Workspace Access Tokens and OAuth “workspace” scope require Business/Enterprise and Grain verification.
- pricing/plan constraints: Workspace API is Business/Enterprise only; personal-scope API is available on Free/Pro.
- app review: Required to use OAuth workspace scope (“clients verified by Grain”).

API surface
- api_breadth: broad (recordings, clips/highlights, playlists/stories, uploads, users, teams, meeting types, webhooks, etc.)
- Base URL: https://api.grain.com
- Versioning: Required Public-Api-Version header (current: 2026‑10‑01)
- Rate limits: 30-token bucket, refill 2 req/sec (≈120 rpm) per token

MCP
- mcp: official (Grain operates an official MCP server at https://api.grain.com/_/mcp with documented tools)

Buildability for Composio
- buildability: ready_with_caveats
- Why: You can ship today using OAuth2 (personal scope) or PATs; rich endpoints and official MCP exist. Caveats: workspace-wide access and some MCP tools/features are gated to Business/Enterprise and/or require client verification; modest rate limits; no sandbox.
- blocker: app_review
  - Details: OAuth workspace scope only for verified clients; Workspace tokens only on paid plans (Business/Enterprise).

Other developer notes
- OpenAPI spec: none public (docs are prose/HTML; no openapi.json found).
- Webhooks: yes (“Hooks” for recording/highlight/story/upload events).
- Sandbox: no (test against live workspace; use PAT scoped to your account).
- OAuth client options: Server-side clients require a registered client_id/secret; public clients (no secret) can self‑declare via hosted client metadata document.

Product fit snapshot
- Good for: Agents that need to fetch transcripts, notes, action items, or run meeting searches; uploading external recordings; reacting to new meetings via webhooks; MCP-based retrieval and reports in Claude/ChatGPT.
- Caveats to design around:
  - Personal vs workspace scope: personal-scope tokens see only what the user can see; workspace-wide requires Business/Enterprise and verified OAuth client or a WAT.
  - Rate limits: 2 req/sec per token; batch thoughtfully and use includes/filters.
  - No sandbox: use a dev workspace or a personal PAT for testing.
  - Some MCP tools (deals/coaching) require Business/Enterprise. ([developers.grain.com](https://developers.grain.com/mcp/faq.html?utm_source=openai))

Checklist for Composio
- OAuth2: Support Authorization Code + PKCE; allow client-metadata flow for public clients and standard client_id/secret for server apps. ([developers.grain.com](https://developers.grain.com/authentication.html))
- Tokens: Implement PAT and WAT bearer auth; surface “personal” vs “workspace” scope clearly. ([developers.grain.com](https://developers.grain.com/authentication.html))
- Endpoints to cover first: recordings (list/get with includes), transcripts/notes/action items, uploads create/promote, users/teams, hooks CRUD. ([developers.grain.com](https://developers.grain.com/endpoints.html))
- Webhooks: Expose hook creation for recording_added/updated and upload_* to avoid polling. ([developers.grain.com](https://developers.grain.com/hooks.html))
- MCP: Provide a Grain MCP toolset integration option (endpoint https://api.grain.com/_/mcp). ([grain.com](https://grain.com/release-notes?utm_source=openai))
