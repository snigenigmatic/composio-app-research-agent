- Docs URL: https://docs.attio.com/

Detail
- Authentication
  - OAuth 2.0 Authorization Code flow supported; tokens can be workspace- or user‑level; PKCE required for user‑level. Tokens are used as Bearer; Basic is also accepted. API keys (single‑workspace access tokens) can be generated from the UI. ([docs.attio.com](https://docs.attio.com/rest-api/guides/authentication.md))
- Credentials access and gating
  - “Available on all plans. Admins can create and manage API keys.” (self‑serve, including Free). ([attio.com](https://attio.com/help/reference/apps/generating-an-api-key))
  - For public distribution, apps are reviewed and listed in the App Store; unpublished apps are limited to 25 installs. (app review for true public/OAuth scale). ([docs.attio.com](https://docs.attio.com/share/the-publication-lifecycle.md))
- API surface
  - Large REST surface covering objects/records, lists, entries, activities, views, webhooks, sequences, users, deals, etc.; also a gated SQL endpoint. ([docs.attio.com](https://docs.attio.com/llms.txt))
- Rate limits
  - 100 RPS reads / 25 RPS writes across the API; score‑based limits for certain list/query endpoints. ([docs.attio.com](https://docs.attio.com/rest-api/guides/rate-limiting.md))
- Webhooks
  - Listed as a core capability in the developer platform page; webhook endpoints and event references are documented. ([attio.com](https://attio.com/platform/developers))
- MCP
  - “Attio MCP is Attio’s hosted MCP server… Authenticates as your Attio user with OAuth.” Official, first‑party. ([docs.attio.com](https://docs.attio.com/mcp/overview.md))
- Plan notes (developer features)
  - Pricing page lists “API and webhooks,” “MCP server,” “App SDK” under Platform & developer for plans; “SQL access through the API and MCP” is not on Free/Plus/Pro and is included on the top tier (listed as Ultra on pricing; older docs call it Enterprise). ([attio.com](https://attio.com/pricing?popup=true))
- Developer/sandbox
  - Attio will provide isolated development workspaces on request; also a 14‑day Pro trial for new workspaces. ([docs.attio.com](https://docs.attio.com/share/the-publication-lifecycle.md))

Composio integration assessment
- What we’d use for auth (primary_auth): OAuth2 (Authorization Code). We should request user‑ or workspace‑level tokens depending on tools; prefer OAuth for multi‑tenant. API keys can support single‑workspace setups.
- Access model: self_serve_free — any workspace (including on Free) can generate an API key; developers can create OAuth apps in the developer console without sales. Public distribution via App Store requires review (app_review).
- API breadth: broad — dozens of endpoints including CRUD for objects/records, list entries, activities, views, webhooks, etc. Good fit for an agent toolkit.
- MCP: official — Attio hosts its own MCP server with OAuth; that can be an alternate or complement to direct REST calls.
- Buildability: ready_with_caveats — we can ship now using OAuth and/or API keys. Caveats: publishing a public OAuth app to surpass the 25‑workspace cap requires Attio app review; SQL endpoints (useful for analytics/agent retrieval) are only on the top tier, so not universally available; observe documented rate limits.
- Likely blocker to wide rollout: app_review (for public app distribution) and paid_plan for SQL (if we intend to expose SQL tools).
