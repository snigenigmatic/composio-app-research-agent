- Webhooks: none found in docs
- Sandbox: no separate sandbox; free plan + per‑plan quotas act as dev environment

What this means for an agent toolkit
- Auth: Developers self‑generate API keys in the Consensus “API & MCP Dashboard” and send them as x-api-key. MCP clients use OAuth sign‑in on supported platforms, but REST integrations are key-based.
- Gating: Free plan yields a key and 30 calls/month; higher quotas/features (pagination, full‑text excerpts, complete text) require paid plans; additional usage is metered ($0.05/call) on paid tiers. Rate limit is 1 req/sec on self‑serve plans.
- Scope: Useful endpoints today include GET /v1/search, POST /v1/threads with polling and follow‑ups, GET /v1/papers/full_text, plus beta endpoints for citations/references. That’s enough to ship, but usage limits and paid features are constraints.

Notes and clarifications
- OAuth: Docs do not describe an OAuth2 flow for the REST API; MCP connectors use OAuth sign‑in on hosted clients, and MCP can also use an API key as a Bearer token. REST integrations should use x-api-key. ([docs.consensus.app](https://docs.consensus.app/api-plans-and-access.md))
- Enterprise: Custom rate limits and volumes require contacting sales; REST still authenticates via x‑api‑key. ([docs.consensus.app](https://docs.consensus.app/api-plans-and-access.md))
