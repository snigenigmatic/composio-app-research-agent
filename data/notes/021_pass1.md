Here are the integration research notes for Slack.

- Product: Slack — team messaging and collaboration with a rich platform for apps, automations, and bots.

- Docs URL: https://docs.slack.dev

- Auth model
  - auth_methods: OAuth2 | Bot token | Bearer/PAT token (user tokens, app-level tokens). Slack apps use OAuth 2.0 to obtain bot/user tokens; token types include user, bot, and app tokens. ([docs.slack.dev](https://docs.slack.dev/authentication/))
  - primary_auth: OAuth2. ([docs.slack.dev](https://docs.slack.dev/authentication/))

- Access to credentials
  - access: self_serve_free — anyone can create an app and get OAuth client credentials; unlisted distribution is allowed; listing in the Slack Marketplace requires approval. ([docs.slack.dev](https://docs.slack.dev/app-management/distribution/))

- API surface
  - api_breadth: broad — Web API (hundreds of RPC-style methods), Events API, interactivity, slash commands, webhooks, admin and SCIM APIs. ([docs.slack.dev](https://docs.slack.dev/apis/web-api/?utm_source=openai))
  - Notable plan gating: SCIM and many admin.* methods require Enterprise Grid/Business+ and admin installation. ([docs.slack.dev](https://docs.slack.dev/admins/scim-api/?utm_source=openai))

- MCP (Model Context Protocol)
  - mcp: official — Slack provides an official MCP server and Slackbot MCP client. ([docs.slack.dev](https://docs.slack.dev/changelog/2026/02/17/slack-mcp?utm_source=openai))

- Buildability for an agent toolkit (Composio)
  - buildability: ready_with_caveats — credentials and core APIs are self-serve and well-documented; however, Marketplace listing requires app review, some APIs need Enterprise/Business+ and admin scopes, and rate limits must be handled. ([docs.slack.dev](https://docs.slack.dev/app-management/distribution/))
  - blocker: app_review — required for Marketplace (listed) distribution; unlisted installs are allowed but some workspaces restrict to Marketplace-only apps. ([docs.slack.dev](https://docs.slack.dev/app-management/distribution/))

- OpenAPI spec: Exists but archived/stale (slackapi/slack-api-specs repo archived; still provides an OpenAPI 2.0 spec for the Web API). ([github.com](https://github.com/slackapi/slack-api-specs?utm_source=openai))

- Webhooks: Yes — Incoming Webhooks for posting; Events API delivers webhooks to your endpoint; request signing provided. ([api.slack.com](https://api.slack.com/messaging/webhooks?utm_source=openai))

- Sandbox: Yes — free Developer Sandboxes (Enterprise org environments) available via the Slack Developer Program. ([docs.slack.dev](https://docs.slack.dev/tools/developer-sandboxes/?utm_source=openai))

- Other notes for implementers
  - Rate limits: HTTP APIs return 429 with Retry-After; per-method tiers apply. ([docs.slack.dev](https://docs.slack.dev/apis/web-api/rate-limits/?utm_source=openai))
  - Distribution: enabling unlisted distribution gives a shareable “Add to Slack” URL; Marketplace apps undergo review. Workspace admins can require approval or allow only Marketplace apps. ([docs.slack.dev](https://docs.slack.dev/app-management/distribution/))
