Here are the integration research notes for Gumroad.

- Product: Gumroad — hosted commerce for creators to sell digital goods, memberships, and more.
- Docs URL: https://gumroad.com/api
- Auth methods: OAuth2; Bearer/PAT token (personal access token generated in the UI). ([gumroad.com](https://gumroad.com/help/article/280-create-application-api))
- Primary auth for multi-tenant agents: OAuth2. ([gumroad.com](https://gumroad.com/help/article/280-create-application-api))
- How to get credentials (self-serve):
  - In any Gumroad account, go to Settings → Advanced → create an application. For own-account automation, click Generate access token to get a long‑lived access_token. For multi‑account apps, use the OAuth redirect flow to exchange the authorization code at https://api.gumroad.com/oauth/token. ([gumroad.com](https://gumroad.com/help/article/280-create-application-api))
- Access: self_serve_free (no plan gating; app and token creation is self‑serve in account settings). ([gumroad.com](https://gumroad.com/help/article/67-the-settings-menu?utm_source=openai))
- API surface (breadth): moderate — v2 REST covers core objects such as products (read), sales/memberships, license verification, and webhooks via “resource subscriptions.” Note: vendor help says license verification requires product_id; product create/edit/upload via public REST is unclear and may be limited. ([gumroad.com](https://gumroad.com/help/article/76-license-keys?utm_source=openai))
- Webhooks: yes — two mechanisms:
  - Ping webhook configured in Settings → Advanced. ([gumroad.com](https://gumroad.com/help/article/67-the-settings-menu?utm_source=openai))
  - Resource Subscriptions API (webhooks) for events like sales/subscription changes. ([gumroad.com](https://gumroad.com/help/article/82-membership-products?utm_source=openai))
- OpenAPI spec: none official found (docs are on gumroad.com/api; no vendor OpenAPI published). ([apitracker.io](https://www.apitracker.io/a/gumroad/specifications?utm_source=openai))
- Sandbox: no dedicated API sandbox; test purchases exist (you won’t be charged buying your own product while logged in). ([gumroad.com](https://gumroad.com/help/article/62-testing-a-purchase))
- MCP: official — Gumroad runs its own MCP server; Claude/ChatGPT connectors documented, with Claude custom connector URL https://gumroad.com/claude/v1/mcp. ([gumroad.com](https://gumroad.com/help/article/355-connect-ai-assistants-to-gumroad))
- Buildability for Composio: ready_with_caveats
  - Why: Self‑serve OAuth and PAT are available and docs exist; webhooks supported. Caveats: no official OpenAPI; parts of the public REST for product creation/file uploads are either undocumented or limited; “Ping” isn’t signed; rate limits not documented in vendor help. Use OAuth2 for user‑by‑user installs; prefer Resource Subscriptions over Ping when you need more than sale pings. ([gumroad.com](https://gumroad.com/help/article/280-create-application-api))
- Blocker: none

Notes and key details for implementers
- Scopes/permissions: OAuth authorize and token endpoints are documented; scopes are passed in the OAuth authorize URL. Example authorize and token exchange are shown in help. ([gumroad.com](https://gumroad.com/help/article/280-create-application-api))
- License keys: Public verification endpoint requires product_id for products created on/after Jan 9, 2023. ([gumroad.com](https://gumroad.com/help/article/76-license-keys?utm_source=openai))
- Endpoints previewed in help:
  - GET /v2/products (example curl in help) and OAuth flows. ([gumroad.com](https://gumroad.com/help/article/280-create-application-api))
