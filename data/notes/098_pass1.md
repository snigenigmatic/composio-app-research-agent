Here are my integration research notes for Mermaid CLI.

- Product: Mermaid CLI
- One-line description: Open-source command-line tool (mmdc) to render Mermaid diagrams to SVG/PNG/PDF and to transform Markdown containing Mermaid code.
- Docs URL: https://github.com/mermaid-js/mermaid-cli
- auth_methods: None (local/open)
- primary_auth: None (local/open)
- access: no_public_api
- api_breadth: none
- mcp: none known (for the CLI itself). Note: Mermaid the service offers an official hosted MCP server that renders/validates diagrams, but that is a separate hosted product, not the CLI.
- buildability: blocked
- blocker: local_tool_only (CLI/library, not a hosted API)
- OpenAPI spec: No
- Webhooks: No
- Sandbox: No

Why: Mermaid CLI is a local tool and npm package you run as a binary (mmdc) or call via a local Node API. There is no hosted, multi-tenant web API, no OAuth, and no developer credential flow to integrate as a SaaS connector.

Evidence snippets
- purpose/what it is | https://github.com/mermaid-js/mermaid-cli/blob/master/README.md | “This is a command-line interface (CLI) for mermaid. It takes a mermaid definition file as input and generates an SVG/PNG/PDF file as output.”
- usage is local CLI, not web API | https://github.com/mermaid-js/mermaid-cli/blob/master/README.md | “mmdc -i input.mmd -o output.svg”
- programmatic use is a local Node API (not hosted) | https://github.com/mermaid-js/mermaid-cli/blob/master/README.md | “It’s possible to call mermaid-cli via a Node.JS API.”

- FYI: separate, hosted MCP server exists (not the CLI) | https://mermaid-25331.zendesk.com/hc/en-us/articles/51112817195923-Mermaid-MCP-Server | “The Mermaid MCP Server is an AI integration that lets AI assistants… generate, validate, and render Mermaid diagrams… [It is] a hosted backend… With authentication: saves the diagram directly to your Mermaid account.”

Assessment details
- Auth model: No authentication—Mermaid CLI is invoked locally (binary or Node import). No OAuth/API keys are documented because there’s no hosted API. ([github.com](https://github.com/mermaid-js/mermaid-cli/blob/master/README.md?plain=1))
- Access/gating: There is no developer credential flow because there’s no remote API; installation is via npm, Docker, etc. ([github.com](https://github.com/mermaid-js/mermaid-cli/blob/master/README.md?plain=1))
- API surface: None as a hosted HTTP API; only a local programmatic interface (Node “run”) and the CLI. ([github.com](https://github.com/mermaid-js/mermaid-cli/blob/master/README.md?plain=1))
- MCP: No MCP server for the CLI itself. Mermaid (the SaaS) does publish an official hosted MCP server with token auth, but it’s distinct from the CLI. ([mermaid-25331.zendesk.com](https://mermaid-25331.zendesk.com/hc/en-us/articles/51112817195923-Mermaid-MCP-Server))
- Buildability for Composio: Blocked. Composio focuses on SaaS/tool APIs callable over the network; Mermaid CLI is a local tool only. If/when integrating Mermaid’s hosted MCP or any future hosted API, that would be a different “app” with token-based auth. ([mermaid-25331.zendesk.com](https://mermaid-25331.zendesk.com/hc/en-us/articles/51112817195923-Mermaid-MCP-Server))

If you want an agent-accessible integration today, consider targeting Mermaid’s official MCP server (hosted) rather than the CLI; it exposes rendering/validation over MCP with bearer-style tokens as described in their help center. ([mermaid-25331.zendesk.com](https://mermaid-25331.zendesk.com/hc/en-us/articles/51112817195923-Mermaid-MCP-Server))
