WhatsApp Business (WhatsApp Business Platform / Cloud API)

- Product description: Meta’s enterprise APIs for sending/receiving WhatsApp messages and calls, plus programmatic account and template management.
- Docs URL: https://developers.facebook.com/documentation/business-messaging/whatsapp/overview
- auth_methods: OAuth2; Bearer/PAT token
- primary_auth: OAuth2
- access: app_review
- api_breadth: broad
- mcp: none known
- buildability: ready_with_caveats
- blocker: app_review
- OpenAPI spec: no official spec published (Meta provides an official Postman collection)
- Webhooks: yes (core to receiving incoming messages and status updates)
- Sandbox: yes (auto-provisioned test WhatsApp account, Messaging account, and phone number when you get started)

Notes and rationale
- Authentication and tokens: Requests use Authorization: Bearer <access_token>. Tokens can be user tokens (for quick tests), long‑lived System User tokens (server-to-server for your own business), or Business Integration System User (BISU) tokens for Tech Providers generated via Embedded Signup with Facebook Login code exchange. ([developers.facebook.com](https://developers.facebook.com/documentation/business-messaging/whatsapp/access-tokens/))
- Permissions and gating: Production, multi-tenant use requires App Review and Advanced access for whatsapp_business_messaging (send/receive) and usually whatsapp_business_management (templates, numbers, webhooks). Clients cannot grant your app these via Embedded Signup unless your app has Advanced access. Direct developers acting on their own data don’t need App Review. This makes access “app_review.” ([developers.facebook.com](https://developers.facebook.com/documentation/business-messaging/whatsapp/permissions/))
- API breadth: Platform includes Cloud API (messaging, calls, groups), Business Management API (templates, numbers, analytics), and Marketing Messages API; extensive references suggest “broad.” ([developers.facebook.com](https://developers.facebook.com/documentation/business-messaging/whatsapp/about-the-platform))
- Webhooks: Webhooks are foundational; all incoming messages and delivery status updates arrive via webhooks. ([developers.facebook.com](https://developers.facebook.com/documentation/business-messaging/whatsapp/about-the-platform))
- Sandbox/dev experience: Getting started auto-creates a test WhatsApp account, Messaging account, and test phone number with relaxed limits and no payment method required to send template messages; supports a quick, self-serve dev flow. ([developers.facebook.com](https://developers.facebook.com/documentation/business-messaging/whatsapp/about-the-platform))
- MCP: No official vendor MCP server is documented for WhatsApp Business; community MCP servers exist but are not official. (No Meta primary source found.)

What Composio can ship now
- Toolkit scope: Send/receive messages; manage templates and media; register/verify numbers; configure and verify webhooks; read analytics where available.
- Auth flow: Use Embedded Signup to mint BISU tokens per connected customer; store and use as Bearer tokens for Graph API calls.
- Caveats: Passing Meta App Review and obtaining Advanced access to required permissions is necessary before customers can grant scopes via Embedded Signup; messaging is usage‑billed; rate limits and template approval flows apply. ([developers.facebook.com](https://developers.facebook.com/documentation/business-messaging/whatsapp/permissions/))
