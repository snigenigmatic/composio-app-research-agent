Zoho Cliq — Integration research notes (as of November 24, 2026)

- Product description: Team chat and collaboration app from Zoho (chats, channels, calls, bots, extensions). 
- Docs URL: Zoho Cliq REST API docs (v2/v3): https://www.zoho.com/cliq/help/restapi/v2/ and OAuth overview: https://www.zoho.com/cliq/help/restapi/v3/oauth/ . ([zoho.com](https://www.zoho.com/cliq/help/restapi/v2/))

Auth model
- auth_methods: OAuth2; Bearer/PAT-style “authtoken/zapikey” supported for some messaging/extension flows. ([zoho.com](https://www.zoho.com/cliq/help/restapi/v3/oauth/))
- primary_auth: OAuth2 (Zoho Accounts). Access token sent as Authorization: Zoho-oauthtoken {token}. ([zoho.com](https://www.zoho.com/cliq/help/restapi/v3/oauth/))

Access/gating
- access: self_serve_free (API available on Free, Standard, Professional, Enterprise; OAuth clients created in Zoho API Console). ([zoho.com](https://www.zoho.com/cliq/plan-comparison.html?zredirect=f))
- notes: No explicit app review mentioned for using Cliq OAuth scopes; Marketplace listing of extensions is optional and separate.

API surface
- api_breadth: broad (users, departments/roles, chats, channels, threads, teams, messages, files, calls/meetings, events, reminders, bots, databases, custom domain/email, bulk export, etc.). ([zoho.com](https://www.zoho.com/cliq/help/restapi/v2/))
- OpenAPI spec: Yes (downloadable OAS for all modules and a complete bundle). ([zoho.com](https://www.zoho.com/cliq/help/restapi/v2/))
- Webhooks: Yes (incoming webhooks with appkey+zapikey; bot/extension webhook handlers). ([zoho.com](https://www.zoho.com/cliq/help/platform/webhook-tokens.html?utm_source=openai))
- Sandbox: No dedicated sandbox called out in docs; self client and regular orgs used for development (not a separate sandbox environment). ([zoho.com](https://www.zoho.com/cliq/help/restapi/v2/registerclient/))

MCP (Model Context Protocol)
- mcp: official (Zoho-published “Zoho Cliq MCP Server” to expose Cliq tools to MCP clients). ([zoho.com](https://www.zoho.com/cliq/mcp-server.html?utm_source=openai))

Buildability for an agent toolkit
- buildability: ready (self-serve OAuth, rich documented API, OpenAPI spec, webhooks; MCP server exists if using MCP-native agents).
- blocker: none
- caveats: Per-endpoint rate limits and fine-grained scopes; multi-DC base URLs must match the customer’s region. ([zoho.com](https://www.zoho.com/cliq/help/restapi/v2/messages/))

How a developer gets credentials
- Create an OAuth client in Zoho API Console (server-/client-/mobile-/non-browser/self-client). Receive client_id/client_secret, then do standard OAuth 2.0 code flow to get access/refresh tokens. ([zoho.com](https://www.zoho.com/cliq/help/restapi/v2/registerclient/))

Summary classification
- auth_methods: OAuth2; Bearer/PAT token (zapikey/authtoken)
- primary_auth: OAuth2
- access: self_serve_free
- api_breadth: broad
- mcp: official
- buildability: ready
- blocker: none

Additional pointers
- Docs highlight multi–data center base URLs; use the customer’s dc (e.g., .com, .eu, .in, .au, .cn, .jp, .sa, .uk, .zohocloud.ca). ([zoho.com](https://www.zoho.com/cliq/help/restapi/v2/))
- Messaging APIs can also be accessed with a single “Webhooks” scope; many other fine-grained scopes exist (Messages.READ/UPDATE/DELETE, etc.). ([zoho.com](https://www.zoho.com/cliq/help/restapi/v2/messages/))
- Incoming webhook tokens (appkey+zapikey) exist for extensions/bots if you need key-based posting without full OAuth. ([zoho.com](https://www.zoho.com/cliq/help/platform/webhook-tokens.html?utm_source=openai))
