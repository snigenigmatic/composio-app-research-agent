Discord — Communications and Messaging

Summary judgment
- auth_methods: OAuth2; Bot token. ([github.com](https://github.com/discord/discord-api-docs/blob/main/developers/topics/oauth2.mdx))
- primary_auth: OAuth2 (install flow with bot scope; the bot then uses its bot token for API calls). ([github.com](https://github.com/discord/discord-api-docs/blob/main/developers/topics/oauth2.mdx))
- access: self_serve_free (create an app in the Developer Portal; get client ID/secret and a bot token). ([github.com](https://github.com/discord/discord-api-docs/blob/main/developers/topics/oauth2.mdx))
- api_breadth: broad (HTTP API, Gateway events, interactions, webhooks, commands, guilds/channels/messages, etc.). ([github.com](https://github.com/discord/discord-api-docs/blob/main/developers/quick-start/getting-started.mdx))
- mcp: community (multiple third‑party MCP servers exist; no official MCP server from Discord found). ([github.com](https://github.com/ExilProductions/discord-mcp?utm_source=openai))
- buildability: ready_with_caveats
- blocker: app_review (App Verification required >100 servers; Privileged Intents require review once app exposure ≥10,000 users, with annual re‑review). ([support-dev.discord.com](https://support-dev.discord.com/hc/en-us/articles/23926564536471-How-Do-I-Get-My-App-Verified?utm_source=openai))

One‑line product description
- Discord is a real‑time communications platform (text, voice, video) with a full developer platform for bots, apps, webhooks, and game/social SDKs. ([github.com](https://github.com/discord/discord-api-docs/blob/main/developers/platform/bots.mdx?utm_source=openai))

Docs URL
- https://docs.discord.com/developers (official developer documentation). ([github.com](https://github.com/discord/discord-api-docs))

OpenAPI spec, webhooks, sandbox
- OpenAPI spec: Yes, official OpenAPI 3.1 “public preview” in discord/discord-api-spec (stable openapi.json and preview spec). ([github.com](https://github.com/discord/discord-api-spec/blob/main/README.md?utm_source=openai))
- Webhooks: Yes. Supports incoming webhooks and “webhook events” (outgoing HTTP callbacks). ([github.com](https://github.com/discord/discord-api-docs/blob/main/developers/platform/webhooks.mdx?utm_source=openai))
- Sandbox: No dedicated sandbox environment; typical workflow is to create an app and install it to a test server, run locally, and expose an interaction endpoint (e.g., via ngrok). ([github.com](https://github.com/discord/discord-api-docs/blob/main/developers/quick-start/getting-started.mdx))

Notes and caveats for an agent toolkit
- Authentication model: Users “install” your app/bot to their guild via OAuth2 using the bot scope (optionally also request user scopes for identity/guilds). Your service uses the bot token to call most APIs and the Gateway; user Bearer tokens from OAuth2 are for user-scoped endpoints only. Self-bots (controlling user accounts) are prohibited. ([github.com](https://github.com/discord/discord-api-docs/blob/main/developers/topics/oauth2.mdx))
- Scale/Review gating: 
  - App Verification: Required to scale past 100 servers. ([support-dev.discord.com](https://support-dev.discord.com/hc/en-us/articles/23926564536471-How-Do-I-Get-My-App-Verified?utm_source=openai))
  - Privileged Gateway Intents (Guild Members, Presence, Message Content): self‑serve toggle below exposure to 10,000 users; at ≥10,000 users, you must apply; annual re‑application required; installs are not blocked during review. ([support-dev.discord.com](https://support-dev.discord.com/hc/en-us/articles/40281523410967-Changes-to-Privileged-Intent-Access-for-Discord-Apps))
  - Some OAuth2 scopes and features are partner‑only (e.g., certain activities/voice scopes). ([github.com](https://github.com/discord/discord-api-docs/blob/main/developers/topics/oauth2.mdx))
- Events and I/O: Besides the Gateway, Discord now supports “webhook events” for receiving notifications over HTTP, useful for agent backends that prefer webhooks over persistent websockets. ([github.com](https://github.com/discord/discord-api-docs/blob/main/developers/platform/webhooks.mdx?utm_source=openai))

Buildability assessment
- Ready with caveats: Credentials are self‑serve and docs/tooling are solid; however, distribution at scale and some data feeds require review/approval, and partner‑only scopes may be unavailable. Primary blockers to flag in productization: app_review (verification + privileged intents review). ([support-dev.discord.com](https://support-dev.discord.com/hc/en-us/articles/23926564536471-How-Do-I-Get-My-App-Verified?utm_source=openai))
