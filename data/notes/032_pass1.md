Here’s what I found for Meta Ads (Meta Marketing API).

- primary_auth: OAuth2
- auth_methods: OAuth2; Bearer/PAT token (system user access token)
- access: app_review
- api_breadth: broad
- mcp: official
- buildability: ready_with_caveats
- blocker: app_review

Product description
- The Meta Marketing API is a set of Graph API endpoints to create/manage campaigns, ad sets, ads and creatives, manage catalogs/audiences, and pull ads insights across Meta surfaces.

Docs URL
- https://developers.facebook.com/documentation/ads-commerce/marketing-api ([developers.facebook.com](https://developers.facebook.com/documentation/ads-commerce/marketing-api?utm_source=openai))

OpenAPI spec, webhooks, sandbox
- OpenAPI spec: No official OpenAPI; Meta publishes official Postman collections for the Marketing API. ([postman.com](https://www.postman.com/meta/facebook-marketing-api/overview?utm_source=openai))
- Webhooks: Yes (Graph API Webhooks for real‑time notifications to your callback URL). ([developers.facebook.com](https://developers.facebook.com/docs/graph-api/webhooks/?locale=en_US&utm_source=openai))
- Sandbox: No separate sandbox environment; use Development Mode, test users, and/or your own ad account for testing before App Review. (Meta explicitly describes OAuth2 and pre‑App‑Review testing with roles/test users.) ([developers.facebook.com](https://developers.facebook.com/docs/business-management-apis/2tier-bm-solution/pre-app-review-development/?utm_source=openai))

Why these classifications
- primary_auth/auth_methods: Facebook Login and tokens follow OAuth 2.0; system users can generate server‑side bearer tokens. ([developers.facebook.com](https://developers.facebook.com/docs/business-management-apis/2tier-bm-solution/pre-app-review-development/?utm_source=openai))
- access: While anyone can create an app and start in development with role‑based testing, using Marketing API for other users or higher quotas requires App Review and access levels (e.g., ads_management, business_management, and the Ads Management Standard Access feature). ([developers.facebook.com](https://developers.facebook.com/docs/business-management-apis/2tier-bm-solution/support/?utm_source=openai))
- api_breadth: Reference shows many root nodes (ad accounts, campaigns, ad sets, ads, creatives, users, etc.). ([developers.facebook.com](https://developers.facebook.com/docs/marketing-api/reference/v27.0/?utm_source=openai))
- mcp: Meta operates an official Ads MCP server (https://mcp.facebook.com/ads) that exposes ads capabilities to AI agents. ([developers.facebook.com](https://developers.facebook.com/documentation/ads-commerce/ads-ai-connectors/ads-mcp-server/ads-mcp-server-overview))
- buildability/blocker: It’s buildable now through the standard Graph/Marketing API or via the official Ads MCP server. However, production use typically needs App Review for advanced permissions/features and you’ll be subject to Meta’s rate‑limit tiers. ([developers.facebook.com](https://developers.facebook.com/docs/graph-api/overview/rate-limiting/?utm_source=openai))

Concise implementation notes for an agent toolkit
- Preferred path today: implement OAuth2 (Facebook Login for Business) and/or support the official Ads MCP server to let end‑users connect ad accounts; MCP simplifies tool discovery and consent flows.
- For a first‑party/internal tool (only your own ad accounts), you can often operate with role‑based tokens in development; for multi‑tenant SaaS, plan for App Review (ads_management, ads_read, business_management) and Ads Management Standard Access for usable quotas. ([developers.facebook.com](https://developers.facebook.com/docs/business-management-apis/2tier-bm-solution/get-started?utm_source=openai))
- System Users allow server‑to‑server flows once your business owns the app; tokens can be non‑expiring or 60‑day expiring. ([developers.facebook.com](https://developers.facebook.com/docs/business-management-apis/system-users/install-apps-and-generate-tokens/?utm_source=openai))
