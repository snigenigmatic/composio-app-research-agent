Neo4j — Research notes (Composio integration)

- Product description: Neo4j is a graph database and managed cloud service (Aura) with APIs to provision/manage instances and to query data over HTTPS/Bolt, plus optional GraphQL Data APIs.

- auth_methods: OAuth2 (Aura management API); Basic (Query API to DB); Bearer/PAT token (SSO/OIDC bearer for Query API); API key (Aura GraphQL Data API)
- primary_auth: OAuth2 (Aura API client-credentials flow issuing a Bearer token)
- access: self_serve_free
  - Rationale: Aura accounts (including Free) can self-create API client credentials; DB/query access uses per-instance username/password or SSO without any partner review.
- api_breadth: broad
  - Rationale: Aura API covers instance/project/admin/metrics/activity endpoints; Query API exposes Cypher over HTTPS; optional GraphQL Data APIs.
- mcp: official
- buildability: ready_with_caveats
  - Caveats: multiple auth modes depending on action (Aura mgmt vs data query vs GraphQL); Aura API rate limits vary by plan; no webhook push (polling for state/events).
- blocker: none

- Docs URL: https://neo4j.com/docs/aura/api/overview/
- OpenAPI spec: Yes (Aura API “API Specification” with testable endpoints is published)
- Webhooks: No first-class webhook product documented (events available via API endpoints like activity feed; otherwise connectors e.g., Kafka)
- Sandbox: Neo4j Sandbox exists but is deprecated in favor of AuraDB Free

Notes for Composio design
- What to implement:
  - Aura Management (provisioning/admin): OAuth2 client-credentials to api.neo4j.io/v1 (Bearer access token in Authorization header).
  - Data/query operations: 
    - HTTPS Query API to the database (Basic with instance username/password; or Bearer if customer’s Neo4j is configured for SSO).
    - Optional GraphQL Data API if the customer has created one; auth via API key or JWT (JWKS) as configured.
- Scopes/tenancy:
  - Aura client credentials are created per user account and inherit that user’s roles/permissions across projects/instances.
  - For Query API, credentials are per-instance database users or SSO.
- Rate limits (Aura API): 25 rpm on Free/Pro trial without billing; 125 rpm on Pro with billing, Business Critical, and VDC.
- Webhooks: none documented; use polling (e.g., activity feed v2beta1) or connectors (Kafka/CDC) for change streams.
- MCP: Official Neo4j MCP server exists; could be wired as an alternate agent pathway for query tooling.

Confidence: high for auth, access, and endpoints of Aura API/Query API; medium for “no webhooks” (none found in official docs), but polling/activity-feed and connector patterns are documented.
