Here are the research notes for MongoDB Atlas.

- Product: MongoDB Atlas — fully managed, multi‑cloud developer data platform for MongoDB
- Docs URL: https://www.mongodb.com/docs/atlas/api/

Auth
- auth_methods: OAuth2; Other
  - Notes: OAuth2 service accounts (client credentials) are now the recommended method; legacy programmatic API keys use HTTP Digest auth.
- primary_auth: OAuth2

Access
- access: self_serve_free
  - Notes: Create an Atlas org/project on the free tier and self‑provision service accounts or programmatic API keys in the UI.

API Surface
- api_breadth: broad
  - Notes: The Atlas Administration API covers organizations, projects, clusters, users, networking, backups, logs, alerts, search, vector, and much more. It’s admin/ops only (not data CRUD).

MCP
- mcp: official
  - Notes: MongoDB provides an official Atlas Managed MCP Server and a local MCP server.

Buildability for an agent toolkit
- buildability: ready
- blocker: none
- Notes: You can ship today using OAuth2 service accounts for the Admin API. For data read/write via an agent, use MongoDB’s official MCP server (recommended) since the legacy Data API is EOL; the Admin API is for control-plane operations.

Other implementation details
- OpenAPI spec: Yes (downloadable from the Admin API docs; public OpenAPI repo available)
- Webhooks: Yes (alert notifications to arbitrary HTTP endpoints)
- Sandbox: Yes (Free/M0 “free forever”; also ephemeral free clusters exist)

Key caveats to note
- Admin API doesn’t expose database CRUD; use drivers or the official MCP server for data operations.
- If customers enforce API IP access lists, you may need to register Composio egress IPs or use the Managed MCP path which handles auth/IP for agent clients.
