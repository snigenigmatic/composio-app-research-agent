Here are my research notes for Apify.

- One‑line description: Hosted web‑scraping and automation platform; you run “Actors” via a REST API and fetch structured results from storages.
- Docs URL: https://docs.apify.com/api

Auth model
- auth_methods: Bearer/PAT token; optionally OAuth2 when using the vendor’s hosted MCP server. ([docs.apify.com](https://docs.apify.com/integrations/api))
- primary_auth: Bearer/PAT token (Authorization: Bearer <token> or token query param). ([docs.apify.com](https://docs.apify.com/integrations/api))

Access and gating
- access: self_serve_free (free signup yields API tokens; free monthly credits, no card). ([docs.apify.com](https://docs.apify.com/agents/quickstart))
- app_review: none noted for API token usage (publishing to the Store is separate and not required to use the API).
- paid_plan: not required to obtain credentials (usage beyond free credits is billed per plan/usage). ([docs.apify.com](https://docs.apify.com/agents/quickstart))

API surface
- api_breadth: broad (actors, tasks, runs, datasets, key‑value stores, request queues, schedules, webhooks, logs, users, etc., with full CRUD in many areas). ([docs.apify.com](https://docs.apify.com/api/v2))
- OpenAPI spec: yes (official YAML/JSON available). ([docs.apify.com](https://docs.apify.com/api))
- Webhooks: yes (first‑class webhook resources and events). ([docs.apify.com](https://docs.apify.com/api/v2/webhooks-webhooks))
- Sandbox: no separate API sandbox documented; developers typically use free accounts/tokens for development. ([docs.apify.com](https://docs.apify.com/agents/quickstart))

MCP (Model Context Protocol)
- mcp: official (vendor‑hosted server at https://mcp.apify.com with OAuth or bearer token auth; also a local stdio server and official GitHub repo). ([docs.apify.com](https://docs.apify.com/mcp))

Buildability for an agent toolkit
- buildability: ready — self‑serve creds + comprehensive REST API; official MCP server also available. ([docs.apify.com](https://docs.apify.com/integrations/api))
- blocker: none

Notes for Composio
- Primary integration path: REST API using user‑generated API tokens; scope‑limited tokens are supported for least‑privilege access. ([docs.apify.com](https://docs.apify.com/integrations/api))
- Alternative/adjacent path: Official MCP server supports OAuth sign‑in and bearer tokens; useful when exposing Apify tools directly to MCP‑compatible agents. ([docs.apify.com](https://docs.apify.com/mcp))
- Webhooks and rich storage APIs simplify event‑driven flows and incremental data retrieval. ([docs.apify.com](https://docs.apify.com/api/v2/webhooks-webhooks))
