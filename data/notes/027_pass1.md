App: Telegram
Category: Communications and Messaging

Product description: Cloud-based messaging platform with two main developer surfaces: the HTTPS Bot API for bots/mini apps and the MTProto client API for full-featured clients; plus “Log in with Telegram” for user authentication.

Auth model
- auth_methods: Bot token; Other; OAuth2
- primary_auth: Bot token
  - Notes: Bot API uses a bot token from @BotFather. MTProto uses api_id/api_hash plus MTProto auth (categorized here as “Other”). “Log in with Telegram” provides an OAuth2/OIDC-style login for websites, not for acting on a user’s Telegram account.

Access
- access: self_serve_free
  - Notes: Anyone can create a bot and obtain a token via @BotFather; api_id/api_hash for MTProto are issued self-serve at my.telegram.org.

API surface
- api_breadth: broad
  - Notes: Bot API covers messaging, media, inline mode, payments, web apps, admin, etc. MTProto exposes the full Telegram functionality used by official clients.

MCP server availability
- mcp: community
  - Notes: Multiple community MCP servers exist (e.g., Telethon-based) enabling agents to read/send messages via MTProto or the Bot API.

Buildability for an agent toolkit
- buildability: ready_with_caveats
- blocker: none
  - Why: Credentials are self-serve and docs are comprehensive. Caveats: no user-consent OAuth to act on user accounts (bots act as bots; MTProto “userbot” automation can carry risk and must follow Telegram’s Terms), bots can’t initiate chats with users, and there are rate/broadcasting limits unless using paid broadcasts.

Docs URL
- https://core.telegram.org/bots/api

OpenAPI spec / Webhooks / Sandbox
- openapi_spec: none official
- webhooks: yes (setWebhook supported)
- sandbox: no separate sandbox; develop with real bots/tokens
