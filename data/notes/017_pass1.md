Plain — Support and Helpdesk (plain.com)

One-line description:
- API-first B2B support platform (threads, customers/accounts, help center, workflows, AI/agents) with full GraphQL API parity to the app. ([plain.com](https://www.plain.com/docs/product/what-is-plain))

Auth model:
- auth_methods: API key; OAuth2
- primary_auth: API key
  - Why: Public, workspace-self-serve machine users with scoped API keys and simple Bearer usage. OAuth exists but is workspace-scoped (per-customer app) and best when acting as an individual user; for multi-tenant agent tooling the machine-user key is the most straightforward. ([plain.com](https://www.plain.com/docs/graphql/authentication))

Access to credentials:
- access: self_serve_trial
  - Sign up and start a 7‑day free trial; API, Webhooks, Events, MCP are listed in plan features. After trial, a paid plan is required for production. ([plain.com](https://www.plain.com/pricing))

API surface:
- Style/endpoint: GraphQL over HTTPS at https://core-api.uk.plain.com/graphql/v1; POST with Authorization: Bearer. GraphQL schema downloadable for codegen; in-app API Explorer available. ([plain.com](https://www.plain.com/docs/graphql/introduction))
- api_breadth: broad (customers, accounts, threads, labels, tasks, help center, workflows, etc.). ([plain.com](https://www.plain.com/docs/graphql/introduction))
- Rate limits: per plan; headers documented. ([help.plain.com](https://help.plain.com/article/rate-limits?utm_source=openai))

MCP:
- mcp: official (vendor-hosted MCP server at mcp.plain.com; OAuth user auth). ([plain.com](https://www.plain.com/docs/integrations/mcp-server))

Buildability as a Composio toolkit:
- buildability: ready_with_caveats
- blocker: paid_plan
- Notes/caveats:
  - Credentials are self-serve (trial → paid). ([plain.com](https://www.plain.com/pricing))
  - OAuth apps are workspace-scoped (“app only works in the workspace you created it in”), so a cross-tenant marketplace-style OAuth may require each customer to create/authorize their own OAuth app; machine-user API keys are simpler for an agent integration. ([plain.com](https://www.plain.com/docs/graphql/oauth))
  - Rate limits vary by plan. ([help.plain.com](https://help.plain.com/article/rate-limits?utm_source=openai))

Docs URL:
- https://www.plain.com/docs/graphql/introduction ([plain.com](https://www.plain.com/docs/graphql/introduction))

OpenAPI spec / webhooks / sandbox:
- OpenAPI spec: No (GraphQL; downloadable schema provided). ([plain.com](https://www.plain.com/docs/graphql/schema))
- Webhooks: Yes; HMAC request signing and optional mTLS supported. ([plain.com](https://www.plain.com/docs/webhooks))
- Sandbox: No separate sandbox environment documented; use trial workspace and the in-app API Explorer. ([plain.com](https://www.plain.com/pricing))

Research details (what to implement)
- Auth (API):
  - Create a Machine User, generate scoped API key, send Authorization: Bearer plainApiKey_xxx. IP allowlisting is available; rate limits apply to API-key traffic. ([plain.com](https://www.plain.com/docs/graphql/authentication))
- Auth (OAuth2):
  - Authorization server: https://signin.auth.plain.com (Authorization Code with/without PKCE). Workspace-scoped OAuth apps; tokens call same GraphQL endpoint as Bearer keys. ([plain.com](https://www.plain.com/docs/graphql/oauth))
- API coverage:
  - End-to-end objects: threads, customers, accounts, labels, SLAs, tasks, help center, etc., matching what the app can do. ([plain.com](https://www.plain.com/docs/graphql/introduction))
- MCP:
  - Official remote MCP server for ChatGPT/Claude/Cursor; authenticates via user OAuth; acts with the user’s permissions. ([plain.com](https://www.plain.com/docs/integrations/mcp-server))
