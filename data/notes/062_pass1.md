App: Vercel
Category: Developer, Infra and Data platforms

Summary
- Product: Frontend cloud for building, deploying, and operating web apps. The public REST API lets you manage deployments, projects, domains, env vars, webhooks, etc. ([vercel.com](https://vercel.com/docs/rest-api))
- Docs: https://vercel.com/docs/rest-api ([vercel.com](https://vercel.com/docs/rest-api))

Auth model
- Auth methods supported: 
  - OAuth2 (Sign in with Vercel; Authorization Code flow; access/refresh tokens) — used to call the Vercel REST API on a user’s behalf. ([vercel.com](https://vercel.com/docs/sign-in-with-vercel))
  - Bearer/PAT token (personal access token created in the Vercel dashboard; sent as Authorization: Bearer <token>) — works with the REST API and CLI. ([vercel.com](https://vercel.com/docs/rest-api))
- primary_auth (for a multi-tenant toolkit): OAuth2. Vercel’s OAuth access tokens are used to call the REST API and are time-limited, with refresh tokens to renew. ([vercel.com](https://vercel.com/docs/sign-in-with-vercel))

How developers get credentials
- Personal Access Token (PAT): Create from the Account Tokens page in Settings; choose full-account/team/project scope; copy once; value prefixes vcp_. Use it as Authorization: Bearer. ([vercel.com](https://vercel.com/docs/accounts/access-tokens))
- OAuth app (Integration): Create an Integration from the Integrations Console; you’ll receive a client (integration) ID and secret; use OAuth endpoints to exchange code for tokens. Public listing requires review and thresholds (see Access). ([vercel.com](https://vercel.com/docs/integrations/create-integration))

Access (gating)
- app_review: 
  - “Once your integration is approved, you can share it for users to install” for connectable-account integrations; native integrations then need to be published. Public marketplace listing requires ≥500 active installs and a review email to integrations@vercel.com. ([vercel.com](https://vercel.com/docs/integrations/create-integration))
- Note: For immediate use without review, users can supply their own PAT; however marketplace distribution and broader OAuth production flows are review-gated. ([vercel.com](https://vercel.com/docs/accounts/access-tokens))

API surface
- Breadth: broad. Current reference lists many resource groups (Deployments, Projects, Domains, DNS, Environment, Teams, Integrations, Marketplace, Webhooks, Sandboxes, Security, etc.) and shows 4+ Webhooks endpoints. Base URL https://api.vercel.com. ([vercel.com](https://vercel.com/docs/rest-api))

MCP
- mcp: official. Vercel MCP is Vercel’s official remote MCP server at https://mcp.vercel.com (OAuth-protected) for docs search, projects/deployments management, logs, and analytics. ([vercel.com](https://vercel.com/docs/mcp))

Buildability for Composio
- buildability: ready_with_caveats
- Why: Full, well-documented REST API and self-serve PATs make it buildable now; using first-class OAuth (preferred for multi-tenant) requires integration approval and, for public listing, meeting marketplace review/thresholds. Webhooks and broad resources support rich tool coverage. ([vercel.com](https://vercel.com/docs/rest-api))
- blocker: app_review

Other implementation notes
- OpenAPI spec: Yes — maintained at openapi.vercel.sh (used to generate docs). ([github.com](https://github.com/vercel/community/discussions/646))
- Webhooks: Yes — account and integration webhooks, documented payloads, security via x-vercel-signature HMAC. ([vercel.com](https://vercel.com/docs/webhooks/webhooks-api))
- Sandbox: No separate API “sandbox” environment; use real accounts with scoped tokens. (Vercel “Sandboxes” is a product area, not a separate API test org.) Evidence is implicit from token prerequisites and docs; no distinct API sandbox is documented. ([vercel.com](https://vercel.com/docs/accounts/access-tokens))
