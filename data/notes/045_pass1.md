Magento (Adobe Commerce) — Research notes (as of November 24, 2026)

- Product description: Adobe Commerce (formerly Magento) is an e‑commerce platform offered as open-source (Magento Open Source), PaaS/on‑prem (Adobe Commerce), and a managed SaaS (Adobe Commerce as a Cloud Service), with REST and GraphQL APIs for storefront and back‑office.

- primary_auth: HMAC/signature
- auth_methods: HMAC/signature (OAuth 1.0a integrations), Bearer/PAT token (admin/customer tokens), OAuth2 (IMS, SaaS)
- access: self_serve_free
  - Rationale: Merchants/admins can create OAuth 1.0a “Integrations” or issue admin/customer tokens on any instance; on SaaS, a merchant org can self‑provision OAuth2 credentials in Adobe Developer Console. No central app review to obtain API credentials.
- api_breadth: broad
- mcp: community
  - Third‑party MCP servers/modules exist for Magento/Adobe Commerce; no official vendor MCP server for store operations (Adobe’s MCP content today targets developer tooling rather than a store‑operational MCP).
- buildability: ready_with_caveats
  - Notes: Per‑instance base URL and deployment type (PaaS vs SaaS) determine auth flow and available endpoints; version/API coverage varies by store; merchants must approve an Integration (OAuth1.0a) or provide/store‑scoped tokens or SaaS IMS credentials.
- blocker: other

- Docs URL: https://developer.adobe.com/commerce/webapi/

- OpenAPI spec: Yes. Swagger/OpenAPI available per instance (e.g., <base>/swagger; JSON schema via /rest/<store>/schema).
- Webhooks: Yes. Adobe Commerce provides first‑party webhooks (Admin > System > Webhooks …) and a Webhooks API; SaaS uses OAuth credentials in Admin; PaaS/on‑prem define auth headers/config for hooks.
- Sandbox: No public, centralized sandbox. Use local installs and each merchant’s non‑prod environments (Cloud “Integration/Staging/Production”) for testing.

How to get credentials (summary)
- PaaS/on‑prem:
  - OAuth 1.0a “Integration” (merchant approves; HMAC‑signed requests with consumer key/secret and access token/secret).
  - Admin/customer bearer tokens: obtain via REST (admin login or customer credentials) and send as Authorization: Bearer <token>.
- SaaS (Adobe Commerce as a Cloud Service):
  - OAuth2 via Adobe IMS using Adobe Developer Console (server‑to‑server or user flows). Traditional admin/integration tokens are not supported on SaaS.

API surface highlights
- REST: broad coverage (catalog, carts/quotes, checkout, orders, customers/companies, CMS, price rules, inventory, etc.). Endpoints differ between PaaS and SaaS; on SaaS, many shopper features are via GraphQL.
- GraphQL: storefront‑optimized schema; JWT tokens for customer/admin; admin token required for some staged content reads.
