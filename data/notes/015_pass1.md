Here’s what I found on Pylon (usepylon.com).

- primary_auth: Bearer/PAT token. The REST API uses a static Bearer token you generate in the Pylon dashboard. ([docs.usepylon.com](https://docs.usepylon.com/pylon-docs/developer/api/authentication?utm_source=openai))
- auth_methods: Bearer/PAT token (REST API); OAuth2 (for the official MCP server only). ([docs.usepylon.com](https://docs.usepylon.com/pylon-docs/developer/api/authentication?utm_source=openai))
- access: paid_plan. API access is included on paid tiers; trials exist but are sales-assisted, not self‑serve. ([usepylon.com](https://www.usepylon.com/pricing))
- api_breadth: broad. The API covers accounts, contacts, issues, messages, KB, macros, tags, tasks/projects, surveys, teams, roles/users, etc. ([docs.usepylon.com](https://docs.usepylon.com/pylon-docs/developer/api/api-reference))
- mcp: official. Vendor‑hosted MCP at mcp.usepylon.com using OAuth. ([support.usepylon.com](https://support.usepylon.com/articles/2407390554-connecting-to-the-pylon-mcp-server?utm_source=openai))
- buildability: ready_with_caveats. You can build today against the REST API with user‑supplied API tokens; sandbox is Enterprise‑only and pricing is paid seats + credits; MCP requires interactive OAuth (no headless API keys). ([usepylon.com](https://www.usepylon.com/pricing))
- blocker: paid_plan

- B2B‑focused, AI‑powered omnichannel support platform (tickets/issues from Slack, email, chat, portal) with an extensive REST API and an official MCP server. ([support.usepylon.com](https://support.usepylon.com/articles/4220063775-platform-orientation-pylon-101?utm_source=openai))

OpenAPI, webhooks, sandbox
- OpenAPI spec: Present in docs (embedded OpenAPI 3.0 JSON snippets per endpoint); no standalone openapi.json publicly advertised. ([docs.usepylon.com](https://docs.usepylon.com/pylon-docs/developer/api/api-reference/issues.md))
- Webhooks: Yes (outbound webhooks via Triggers; inbound webhooks to trigger Automations). ([docs.usepylon.com](https://docs.usepylon.com/pylon-docs/developer/webhooks?utm_source=openai))
- Sandbox: Yes, listed as “Sandbox Environment” on Enterprise tier. ([usepylon.com](https://www.usepylon.com/pricing))

Notes and nuances for implementers
- API tokens are scoped; actions taken appear under the token’s name. ([docs.usepylon.com](https://docs.usepylon.com/pylon-docs/developer/api/authentication?utm_source=openai))
- Region: endpoints/documentation reference US and EU API bases; SDK/docs show OpenAPI 3 with servers for both regions. ([docs.usepylon.com](https://docs.usepylon.com/pylon-docs/developer/api/api-reference/issues.md))
- Rate limits: documented per‑endpoint (e.g., redact message 20 rpm; bulk issue ops 30 rpm); separate guidance shows higher limits on some streams (e.g., Audit Logs 300 rpm). ([docs.usepylon.com](https://docs.usepylon.com/pylon-docs/developer/api/api-reference/messages?utm_source=openai))
- Webhooks: Outbound configured via Settings > Webhooks + Triggers; inbound automation webhooks require Bearer token on POST to an inbound URL. ([docs.usepylon.com](https://docs.usepylon.com/pylon-docs/developer/webhooks?utm_source=openai))
