Aircall — Integrations research notes

- Product: Aircall (cloud phone and AI customer communications platform)
- Category: Communications and Messaging
- Docs: https://developer.aircall.io

Auth model
- auth_methods: OAuth2, Basic (API ID + API token via HTTP Basic)
- primary_auth: OAuth2 (required for multi-tenant/public integrations; Basic is for a single company account)

Access to credentials
- access: partner_gated (OAuth client ID/secret issued after acceptance to the Technology Partner program; Basic API keys are self-serve for an Aircall customer admin)

API surface
- api_breadth: broad (calls, contacts, users, numbers, tags, conversations, messaging/SMS/WhatsApp, campaigns, webhooks, analytics, etc.)

MCP
- mcp: community (third-party MCP servers exist wrapping Aircall; no official Aircall-provided MCP server)

Buildability for an agent toolkit
- buildability: needs_outreach
- blocker: partner_program
- Rationale: A multi-tenant toolkit should use OAuth; OAuth credentials require Tech Partner approval. Basic Auth is intended for private, single-account use and is restricted in ToS for published apps.

Other notes
- OpenAPI spec: no official spec published (couldn’t find one in official docs; third party notes absence)
- Webhooks: yes (create/list/update/delete; many events)
- Sandbox: no dedicated sandbox environment (test in a normal account; partner “developer account” exists after approval but no separate API sandbox)
- Rate limits: documented (e.g., 120 requests/min/company in API refs)
- Helpful entry points: Authentication overview; OAuth implementation guide; API References; Webhooks docs

Evidence
- Auth methods | https://developer.aircall.io/docs/authentication | “Aircall supports two ways to authenticate with the REST API: Basic Authentication and OAuth.”
- Basic keys are self-serve | https://support.aircall.io/en-gb/articles/10375395181853 | “To access the API securely, Aircall uses API Keys… Enter a key name and copy the API ID and API Key.”
- OAuth requires partner approval | https://developer.aircall.io/docs/oauth | “OAuth credentials — If you haven't received them yet, apply to the Tech Partner program.”
- Public vs private, gating | https://developers.aircall.io/api-references | “If you want to build an App for companies using Aircall… please use the OAuth flow. It is a requirement to be listed on the Aircall App Marketplace… If you are an Aircall customer… the Basic Auth flow will do the trick.”
- Webhooks API scope | https://developers.aircall.io/api-references | “Aircall Public API allows any developer to fetch, create, update and delete Webhooks… With OAuth, only the webhook linked to the token is accessible. With Basic Auth, webhooks created through the Aircall's dashboard and Basic Auth API requests are accessible.”
- No sandbox | https://support.aircall.io/en-gb/articles/23108614387485 | “Currently, Aircall does not offer a dedicated sandbox environment for testing.”
- ToS constraint on Basic vs OAuth | https://aircall.pactsafe.io/versions/64bfbe34d99de9c22b12dd5a.pdf | “Obtain API Credentials for OAuth by registering for a Partner Account. If… using Basic Auth, You may only do so (a) if You are a direct subscriber… or (b) with the express authorization… Aircall may require You to update the Application… so that such Application uses OAuth.”
- MCP status | https://developer.aircall.io/docs/mcp-faqs | “Does Aircall offer an MCP server… As of this writting we don't offer an MCP servier…” 
- MCP community server exists | https://verifymcp.io/servers/io-usefulapi-aircall/aircall | “Aircall MCP by usefulapi” (third‑party)
- OpenAPI spec (3rd party note) | https://pkg.go.dev/github.com/amp-labs/connectors/providers/aircall/metadata | “...based on the Aircall API documentation, as Aircall does not provide an OpenAPI spec...”
