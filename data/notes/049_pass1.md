Amazon Selling Partner (SP-API) — research notes

- Product: Amazon Selling Partner API (SP-API)
- One‑line description: Amazon’s official REST APIs for sellers and vendors to automate catalog, listings, orders, fulfillment/FBA, reports/feeds, finance, and more.
- Docs hub: https://developer-docs.amazon.com/sp-api/docs/welcome

Auth model
- auth_methods: OAuth2 (Login with Amazon; refresh/access tokens). RDT via Tokens API for restricted operations.
- primary_auth: OAuth2

Access and gating
- access: paid_plan (Professional selling account required to create a developer profile/credentials)
- app review/compliance: Roles-based access; public apps and any restricted/PII roles require review and compliance (DPP).
- how to get credentials (high level):
  1) Sign up/log in to Seller Central with a Professional selling account as the primary user; open Developer Central/Solution Provider Portal and create a Developer Profile with requested roles.
  2) Register an app (sandbox first, then production) in the Solution Provider Portal to obtain client_id/client_secret and set redirect URIs.
  3) For public apps, sellers authorize via the Appstore OAuth (LWA) flow; for private seller apps, use self-authorization. Use Tokens API to request RDT when calling restricted operations.

API and developer surface
- api_breadth: broad (dozens of APIs across Catalog, Listings, Orders, Feeds, Reports, Finance, FBA/Inbound/Outbound, Notifications, Vendor, AWD, etc.)
- OpenAPI/Swagger: yes (official “selling-partner-api-models” repo)
- Webhooks: Notifications delivered via Amazon SQS or Amazon EventBridge (no direct HTTPS webhook)
- Sandbox: yes (static and dynamic sandbox endpoints with mock/stateful behavior)
- SDKs/samples: Official models and samples in Amazon GitHub orgs

MCP (Model Context Protocol)
- mcp: official (Amazon publishes MCP servers/samples that expose SP-API tools; also references a hosted “Amazon Selling Partner Connector (MCP)” in amzn GitHub)
  - Notes: Amazon’s amzn/selling-partner-api-samples includes “Local MCP for SP-API” packages/servers; amzn/selling-partner-agentic-toolkit references an Amazon-hosted connector URL.

Buildability for a Composio-style agent toolkit
- buildability: ready_with_caveats
- blocker: app_review
  - Rationale: You can build and test today, but production at scale requires: a paid Professional selling account to register as developer; app review for public apps; roles approvals (and DPP/security for restricted/PII data). Notifications require AWS resources (SQS/EventBridge). RDT handling adds flow complexity.
